# RCA：从研究切片到项目的路线图

> 状态：草稿（2026-11-27）。基线 `main@e2c2fdb`；v1/v2/v3 已签收
> （ADR-0041/0042/0043）。本页只定阶段与门槛，不放宽任何已签收契约。

## 1. 现在在哪

| 阶段 | 内容 | 状态 | 证据 |
| --- | --- | --- | --- |
| 0 | 有指标、有基线、能出 Top-1 | 完成 | v1 `M2-report.md` |
| 1 | 公开数据 + 外部基线 + 冻结契约 | 完成 | v1/v2 契约 |
| 2 | 未见系统复现（纯 holdout） | **完成** | v3：0.744 vs 0.448，+29.6pp，最差故障 +16pp |
| 3 | 自动发现故障（起点自寻） | **失败** | v3 检测：覆盖 30.4%、误报 67.2% |
| 4 | 端到端可用（告警→定位→结论） | 未开始 | 卡在阶段 3 |

**判定**：方法层面已经过“外部可证伪”，项目层面还缺**入口**与**消费者**。
阶段 3 失败否掉的是“全自动”，不是“定位本身可用”——v3 的成立条件恰好是
“起点已知”。这就是两条路线的分岔点。

## 2. 两条路线

### 路线 B：告警入口旁路（先做，便宜，逼近项目）

不自己检出故障，直接从 OpsPilot 既有告警（ADR-0035 台账 / ADR-0030 基线预警）
取时间窗，输出服务排序。它的成立前提是一个可测的问题：

> 真实告警比注入点晚 1–5 分钟，v3 的增益还剩多少？

| 门槛 | 判据 | 说明 |
| --- | --- | --- |
| **B0 入口鲁棒性**（离线，先做） | δ=120s 时 Top-1 相对 δ=0 下降 ≤5pp（SS/OB dev 各自），且任一故障下降 ≤10pp | δ∈{0,30,60,120,300}s；δ=300s 只记录不设门槛 |
| B1 接线可行 | 只读接口，从告警到 Top-3 列表 p95 <30s，无需人工输入真因 | 不写产品面数据、不新增鉴权维度 |
| B2 价值证明 | ≥10 个真实或高保真回放事件，Top-3 含真因 ≥8，且不新增告警噪音 | 需运维人确认，不看离线指标 |

**B0 失败即 B 路作废**：若 2 分钟迟滞就吃掉增益，说明这条路必须先有检测，
直接转 A。

> **B0 结果（2026-11-27）：FAIL。** δ=120s 时 SS 0.960→0.747（−21.3pp）、
> OB 0.893→0.840（−5.3pp），分故障条款同样超限。**路线 B 作废，转路线 A。**
> 详见 `offline/rca/reports/R4-report.md` 与 ADR-0044。

### 路线 A：自建检测（后做，贵，逼近论文）

补阶段 3：新特征（跨服务一致性、持续时间、调用链上下文），不是再调阈值。

| 门槛 | 判据 | 说明 |
| --- | --- | --- |
| A1 dev 检测 | SS/OB dev 覆盖 ≥80% 且误报 ≤5% | 沿用 v2 冻结判据，两套都要过 |
| A2 分故障非回归 | 任一故障类型检出率不得比 3σ 低 >10pp | 防止“整体赢、单类崩” |
| A3 一次性 holdout | 冻结 A1/A2 后 TT 只跑一次；门槛冻结前不得查看 | 沿用 v3 的 holdout 纪律 |

**A 的收益是补全自动化，风险是可能再次证伪；两者都应在 dev 上先见分晓。**

## 3. 决策规则

1. 先跑 B0（离线、dev-only、一周内可出结论）。
2. B0 PASS → 走 B1/B2，A 暂缓；B0 FAIL → B 作废，转 A。
3. 任一阶段失败都按“负结果”写报告，不靠调参抢救，不碰 TT。

## 4. 不做（两条路线共用）

- 不在 TT 上选参、调阈值或挑 seed。
- 不把 67.2% 误报说成“接近可用”，不靠换阈值掩盖。
- 不改 v1–v3 已签收的报告、运行目录与断言。
- 不为“接产品”绕过契约或伪造真实事件。
- 不声称“故障预测 / 性能优化 / 检测已产品化”。

## 5. 下一步

B0 已完成并判 FAIL（见上）。下一步是路线 A 的 A1 契约：新特征（跨服务一致性 /
持续时间 / 调用链上下文）+ dev 上的覆盖 ≥80%、误报 ≤5%、单故障回退 ≤10pp。
新契约冻结前不写实现；TT 仍不参与。

> **A1 结果（2026-11-27）：FAIL。** 16 配置 0 合规：SS 最好 0.840/误报 0，
> OB 最好 0.493/误报 21.3%，分故障亦超限。机制问题：过滤器不新增报警事件，
> 只把 12 个“先误报后真报警”的 case 换成检出、同时丢掉 11 个原有检出，
> 净 +1；兑换预算补不上 0.48→0.80。详见 `offline/rca/reports/A1-report.md`
> 与 ADR-0046。

> **A2' 结果（2026-11-27）：FAIL。** 独立 CUSUM 16 配置 0 合规：
> SS 最好 0.893/误报 5.3%（k=1,h=12,m=2），OB 最好 0.760/误报 14.7%
> （k=1,h=8,m=2）；联合最优 `min(SS,OB)=0.760`。CUSUM 确实能新增检出
> （SS +5、OB +24），但 OB 的 +24 里 19 个只是把 v2 注入前误报后移成检出，
> SS 新增 5 个同时丢掉 6 个；`m=1` 全部在注入前报警。详见
> `offline/rca/reports/A2-report.md` 与 ADR-0049；Lead 已签收 A2 FAIL
> （2026-11-27）。A3 一次性 holdout 不启动。

下一步：A2 已失败，不能用 TT/rep 4–5 抢救，也不在 A2 网格上继续挑
`k/h/m`。若继续路线 A，必须另立契约，先证明新机制能同时改善
