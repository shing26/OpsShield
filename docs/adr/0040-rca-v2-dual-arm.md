# 0040. RCA v2：双检测臂 + 自适应融合，外部验证通过定位/未通过检测误报

- 状态：Proposed（待 Lead 签收）
- 日期：2026-11-26
- 契约：`plans/rca-v2-accept.md`（FROZEN）
- 证据：`offline/rca/reports/V2-report.md`（HEAD `360a52a`）

## 背景

v1（[ADR-0039](0039-rca-detector-slice.md)）的边界很清楚：资源类故障检出后
条件 Top-1 93.3%，但 delay 故障从 100% 掉到 20%，资源型检测器只覆盖 60%。
v2 只解决这两件事，并在**新系统** RE1-SS（Sock Shop）上做外部验证，
RE1-OB 只作回归护栏。

## 决策

1. **检测拆成两臂**：资源臂（cpu/mem/diskio）与 SLI 臂（latency/error）。
   两臂共用只读滚动基线、正向 robust-z、8% 材料性下限、连续 3 点越线；
   唯一可调项是阈值，在 dev 上按「覆盖 ≥80% 且误报 ≤5%」选。
   选中 resource=20 / SLI=8。
2. **定位按显著性自适应融合**：两臂都显著时加权融合（`weighted`），
   仅一臂显著时只用该臂，都不显著时取两臂较大者；拓扑扣减只作用于 SLI 分量。
   选参加硬约束「任一故障类型不比 3σ 低 >5pp」，最终落到默认参数。
3. **v1 方法冻结为 `v1_metric_family`**：v1 的 `topo-first`/`static-threshold`
   只认 `*_latency`，漏读了数据里同时存在的 `latency-50/-90`。AC-3 要求逐 case
   复现 v1，所以 v1 路径保持原语义；v2 方法才使用完整指标族。
4. **v2 不接产品面**：AC-4（聚合增益）、AC-5（分故障非回归）、AC-7（端到端）
   都通过，但 AC-6 的误报率 3/50 = 6.0% 超过 5% 硬线。按判定矩阵不满足
   「三项全 PASS」。

## 证据（RE1-SS 测试集，一次性）

- 定位：`dual-arm` Top-1 0.940 vs 3σ 0.720（+22pp，CI [+10, +36]pp，p=0.0034）；
  五类故障全部 ≥ 3σ（delay 1.000 vs 0.800）。
- 检测：合并覆盖率 0.840、中位 17.5s、P90 26.9s、**误报 3/50**。
- 端到端：`dual-arm` 0.800 vs 3σ 0.640（+16pp，CI [+6, +26]pp）。
- 回归护栏：v1 六方法在 RE1-OB 测试集与 `M2-report.md` 逐 case 一致。

## 否决项

- **把 AC-6 的 6% 说成「接近通过」**：契约写的是 ≤5%，差一个 case 就是失败。
- **用 RE1-SS 测试集调 sustain 或阈值**：测试集已经用掉；dev 网格里
  sustain=5 有 93.3%/4% 的组合，但改 sustain 必须先改契约，且需要新的验证集。
- **把 OB 的 SLI 阈值单独调高**：那是**按系统调参**，会摧毁「外部验证」的意义。
  正确做法是每系统、因果的基线校准（见下）。
- **直接接进告警链**：同一检测器在 RE1-OB dev 上 SLI 臂误报 31/75（41%），
  接进去会把正常流量尖峰变成事故。
- **用「整段前窗 q99」做自适应阈值**：它用尖峰本身校准出抑制尖峰的阈值
  （look-ahead 泄漏）；在线滚动版本在 300s 窗口下压不住尖峰。两者都不采用。

## 后果

- 正面：定位侧第一次在**新系统**上同时赢聚合与分故障；v1 的 delay 崩塌被证明
  伴随指标解析缺陷（v1 漏读 `latency-50/-90`），但两者各占多少未做定量归因。
- 正面：检测的三种失败模式（漏检、前置误报、误报遮蔽真报）都有逐 case 证据，
  不再是只看覆盖率。
- 负面：检测器目前只在 Sock Shop 形态的数据上成立；SLI 臂对正常延迟尖峰没有
  系统无关的判据。
- 负面：契约把 sustain 固定为 3，恰好是本次误报超线的绑定约束；修它需要改契约
  和新验证集。
- 偏差（已披露）：契约 §3.2 括注建议 SLI 臂用 `latency-90 + error`，实现用了完整
  SLI 族；dev 上收窄只少 1 个 case、误报不变，测试集未因此重跑。
- 待办：每系统因果基线校准 → 在 RE1-TT 或新切分上验证 → 再谈产品面。
