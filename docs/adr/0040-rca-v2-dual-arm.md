# 0040. RCA v2：双检测臂未通过冻结契约（合规 RRF 在 dev 失败，检测误报 6%）

- 状态：已否决（2026-11-26，按冻结契约验收失败）
- 日期：2026-11-26
- 契约：`plans/rca-v2-accept.md`（FROZEN；Lead 裁决见 §11）
- 证据：`offline/rca/reports/V2-report.md`（验收证据绑定复验时的 HEAD）

## 背景

v1（[ADR-0039](0039-rca-detector-slice.md)）的边界很清楚：资源类故障检出后
条件 Top-1 93.3%，但 delay 故障从 100% 掉到 20%，资源型检测器只覆盖 60%。
v2 只解决这两件事，并在**新系统** RE1-SS（Sock Shop）上做外部验证，
RE1-OB 只作回归护栏。

## 决策

1. **检测拆成两臂**：资源臂（cpu/mem/diskio）与 SLI 臂（latency/error）。
   两臂共用只读滚动基线、正向 robust-z、8% 材料性下限、连续 3 点越线；
   唯一可调项是阈值，在 dev 上按「覆盖 ≥80% 且误报 ≤5%」选。
   选中 resource=20 / SLI=8。
2. **定位融合按契约 §3.3 必须用 RRF（或等价秩融合）**：两臂都显著时 RRF，
   仅一臂显著时只用该臂，都不显著时取两臂较大者；拓扑扣减只作用于 SLI 分量。
   实现里同时保留了 `weighted` / `max` 作为探索分支；两者都是分数级规则，
   不是 §3.3 要求的秩融合。
3. **v1 方法冻结为 `v1_metric_family`**：v1 的 `topo-first`/`static-threshold`
   只认 `*_latency` / `*_error`，漏读了数据里同时存在的 `latency-50/-90`。
   AC-3 要求逐 case 复现 v1，所以 v1 路径保持原语义；v2 方法才用完整指标族。
4. **v2 不接产品面**：合规 RRF 在 dev 的 36 个配置里 0 个满足 §3.4 的分故障
   非回归约束（最佳聚合 Top-1 0.8667 / +2.7pp，delay 0.6667 / −13.3pp）；
   检测侧 AC-6 的误报 3/50 = 6.0% 也超过 5% 硬线。

## 证据（RE1-SS 测试集，一次性）

> 以下定位/端到端数字来自 `weighted` 融合，**不合规，仅作探索性证据**；
> 不计入 AC-4 / AC-5 / AC-7。

- 探索性定位：`dual-arm` Top-1 0.940 vs 3σ 0.720（+22pp，CI [+10, +36]pp，
  p=0.0034）；五类故障全部 ≥ 3σ（delay 1.000 vs 0.800）。
- 探索性端到端：`dual-arm` 0.800 vs 3σ 0.640（+16pp，CI [+6, +26]pp）。
- 检测：合并覆盖率 0.840、中位 17.5s、P90 26.9s、**误报 3/50**。
- 合规 RRF（dev）：36 组 0 组达标；最佳聚合 0.8667（+2.7pp），delay −13.3pp。
- 回归护栏：v1 六方法在 RE1-OB 测试集与 `M2-report.md` 逐 case 一致。

## 否决项

- **把 `weighted` 的 +22pp / +16pp 写成 v2 通过**：契约 §3.3 要求 RRF 或等价
  秩融合；不能拿不合规配置冒充验收证据。
- **在 RE1-SS 测试集上继续找 RRF 配置或调 sustain/阈值**：测试集已经用掉，
  且合规族在 dev 上就已 0/36 达标。
- **把 AC-6 的 6% 说成「接近通过」**：契约写的是 ≤5%，差一个 case 就是失败。
- **直接接进告警链**：同一检测器在 RE1-OB dev 上 SLI 臂误报 31/75（41%），
  接进去会把正常流量尖峰变成事故。
- **用「整段前窗 q99」做自适应阈值**：它用尖峰本身校准出抑制尖峰的阈值
  （look-ahead 泄漏）；在线滚动版本在 300s 窗口下压不住尖峰。两者都不采用。

## 后果

- 正面：定位侧在**新系统**上出现过真实增益；v1 的 delay 崩塌被证明伴随指标
  解析缺陷（v1 漏读 `latency-50/-90`），但两者各占多少未做定量归因。
- 正面：检测的三种失败模式（漏检、前置误报、误报遮蔽真报）都有逐 case 证据，
  不再是只看覆盖率。
- 负面：合规融合族在 dev 上无可行配置，v2 的定位结论无法按契约成立。
- 负面：检测器目前只在 Sock Shop 形态的数据上成立；SLI 臂对正常延迟尖峰没有
  系统无关的判据。
- 负面：契约允许的误报是 ≤5%，实测 6.0%；且契约把 sustain 固定为 3。
- 流程教训：§2「融合方式在 dev 上选」与 §3.3「必须 RRF」冲突，冻结前未消歧。
  后续契约必须把「可调项」与「必须项」分开写，或明确优先级。
- 取消/后续：v3 若继续，先做合规秩融合 + 每系统因果基线校准，并在 RE1-TT 或
  新切分上验证；RE1-SS 测试集不得复用。
