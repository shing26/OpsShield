# 0041. RCA v3：置信加权秩融合在第三系统复现定位增益，检测仍不可迁移

- 状态：Proposed（待 Lead 签收）
- 日期：2026-11-27
- 契约：`plans/rca-v3-accept.md`（FROZEN）
- 证据：`offline/rca/reports/V3-report.md`（验收证据绑定复验时的 HEAD）

## 背景

v2（[ADR-0040](0040-rca-v2-dual-arm.md)）按冻结契约失败：等权 RRF 在 dev 上
0/36 达标，`weighted` 的 +22pp 只是探索性证据；检测误报 6%。v3 只回答一个
问题：把两臂信号换成合规的“置信加权秩融合”后，定位增益能否在第三个系统
RE1-TT（Train Ticket）上复现。

## 决策

1. **定位融合改为置信加权秩融合（`dual-arm-rrf`）**：两臂都显著时
   `w_res/(60+rank_res) + w_sli/(60+rank_sli)`，其中 `w_*` 是每臂一个标量，
   来自显著性门控已经使用的 `max(arm)`。服务排序只由秩决定，属于契约 §3.3
   允许的“带臂置信度的秩融合”。
2. **RE1-TT 是纯 holdout**：125 个 case 全部作为 test，不参与任何调参；
   选参只用 RE1-SS dev + RE1-OB dev（各 75）。
3. **修复 `to_service`**：从 `split("_")[0]` 改为 `rsplit("_", 1)[0]`，
   兼容 `ts-auth-service_cpu`；对 OB/SS 的 14,170 个列名逐列等价，由 AC-3
   回归锁定。
4. **检测只做零样本诊断，不作为门槛**：沿用 v2 冻结阈值（resource=20 /
   SLI=8 / sustain=3），TT 上不调任何参数；v3 不接产品面。

## 证据

### dev 选参（只看 SS/OB rep 1–3）

- 选中 `τ_res=3 / τ_sli=8 / discount=0.5 / boost=0.3`。
- SS dev：0.960 vs 3σ 0.840（+12.0pp，CI [+4.0, +20.0]pp）。
- OB dev：0.893 vs 3σ 0.693（+20.0pp，CI [+9.3, +30.7]pp）。
- 两套均 36/36 配置满足分故障约束。

### RE1-TT 一次性评估（125 cases，64 候选）

- `dual-arm-rrf` Top-1 **0.744** vs 3σ **0.448**：+29.6pp，
  配对 CI [+18.4, +40.0]pp，McNemar p=1.24e-6。
- 五类故障全部 ≥3σ：cpu +60pp、delay +24pp、disk +24pp、loss +24pp、mem +16pp。
- Top-3 0.864 vs 0.816（+4.8pp，CI [−3.2, +12.8]pp）。
- `dual-arm`（weighted，不合规）0.800，比 rrf 高 5.6pp；SS dev 上 rrf 反而
  高于 weighted（0.960 vs 0.947）。秩融合不是普适最优。

### 检测诊断（非门槛）

- 合并覆盖 30.4%（38/125）、误报 67.2%（84/125）、中位 17s、P90 31.3s。
- 64 个候选服务放大「任一服务报警」的误报；正常尖峰与故障 z 分布重叠。

## 否决项

- **把 `dual-arm-rrf` 说成性能最优**：TT 上 weighted 0.800 > rrf 0.744；
  rrf 是合规要求下的折中，不是普适赢家。
- **在 TT 上继续调阈值/参数/seed**：TT 是一次性 holdout；调参即污染。
- **把检测说成已解决或可产品化**：零样本误报 67.2%，端到端不可用。
- **声称“故障预测 / 性能优化”**：v3 只覆盖“检测起点已知时的定位”。
- **声称拓扑先验在 TT 上有效**：TT 没有调用图，扣减被禁用。

## 后果

- 正面：定位增益第一次在**第三个系统**复现，且相对增益 +29.6pp 是 v1/v2/v3
  中最大的；v2 的“加权只是不合规探索”被一个合规方法替代。
- 正面：`to_service` 修复被 14,170 列等价校验与 v1 回归双重锁定。
- 负面：TT 绝对 Top-1 0.744，低于 SS dev 的 0.960；64 个候选让任务更难。
- 负面：检测零样本迁移失败，且不是阈值问题；需要新特征与独立契约（v4）。
- 负面：TT 无拓扑，v3 没有验证拓扑先验的跨系统有效性。
- 后续：v4 只做检测，先定义可证伪的跨系统判据，在 SS/OB dev 过门槛后再碰
  TT；不要在 TT 上调阈值。
