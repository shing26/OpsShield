# 0047. RCA A2：独立 CUSUM 能新增检出，但覆盖/误报仍不达标

- 状态：Proposed（待 Lead 签收）
- 日期：2026-11-27
- 契约：`plans/rca-detection-a2-accept.md`（FROZEN）
- 证据：`offline/rca/reports/A2-report.md`

## 背景

A1 已证明“在 v2 报警之上加过滤器”不能新增报警事件：合规集 0/16，
OB 覆盖最好只有 0.493、误报 21.3%。路线 A 的 A2' 因此换机制：用独立
CUSUM 在 v2 的 robust-z 序列上自己产生报警，v2 只作逐 case 对照。
判定仍然是 SS 与 OB 两套 dev 同时做到覆盖 ≥80%、误报 ≤5%，且相对 v2
有受控的新增/丢失。

## 决策

**按冻结契约判 A2 FAIL（合规集 0/16），不进入 A3 holdout，不产品化。**

“CUSUM 能新增检出”这一子问题成立；但“同时达到覆盖与误报门槛”不成立，
因此不能把检测能力说成可用。

## 证据

- SS best-effort（k=1, h=12, m=2）：覆盖 **0.893**（67/75），
  误报 **4/75 = 5.3%**，新增 +5 / 丢失 6。
- OB best-effort（k=1, h=8, m=2）：覆盖 **0.760**（57/75），
  误报 **11/75 = 14.7%**，新增 +24 / 丢失 3。
- 联合最优仍是 `k=1, h=8, m=2`：`min(SS, OB) = 0.760`，
  两套误报 9.3% / 14.7%。
- 分故障：SS loss −26.7pp、delay −13.3pp；OB 最差 disk +6.7pp。
- 延迟：中位 15–23.5s、P90 35.0–52.4s；32 次运行迟到报警 0。

## 机制结论

1. **CUSUM 改变了事件集合。** OB 有 4 个 `none→detected`、1 个
   `late→detected`；SS 有 5 个 `none→detected`。这些是 v2 没有的检出，
   说明“换生成规则”确实能突破 A1 的“只重选择”限制。
2. **但 OB 的 +24 主要是后移，不是新发现。** 24 个新增里 19 个原本是
   v2 的注入前误报；CUSUM 把首次报警推后到注入后。真正“v2 无报警 + A2
   检出”只有 4 个，另有 1 个把迟到报警拉回窗内。
3. **SS 的兑换率是负的。** 5 个新增检出换来 4 个新误报和 6 个丢失检出，
   覆盖 0.907→0.893、误报 1→4。
4. **OB 误报从 31 降到 11，但仍超门槛约 3 倍。** 9 个 v2 误报在 CUSUM
   下仍是误报；注入前的持续偏移累积后仍会越线，CUSUM 不是去误报器。
5. **`m=1` 不可用。** SS 8 个 `m=1` 配置全部 75/75 在注入前报警；
   OB 也有 75/75 或 74/75。单指标正常漂移就足以累积越线；可用的 `m=2`
   已经引入了“至少两个指标同时越线”的巧合约束。

## 否决项

- **放宽 AC-3/AC-4/AC-5 让 A2 通过**：门槛在冻结时已固定；失败是机制
  兑换率不够，不是门槛太高。
- **把 CUSUM 与 v2 报警做并集/兜底**：契约禁止；且 v2 在 OB 自身误报
  41.3%，并集只会把误报带回来。
- **看到 dev 结果后改 k/h/m、改分母或改状态口径**：属于调参，违反预注册。
- **用 TT 或 rep 4–5 抢救**：保留集未读；A2 已失败，不允许事后挑数据。
- **把“OB +24 新增”说成检测可用**：覆盖 0.760、误报 14.7% 仍不达标。

## 后果

- 正面：A2 回答了 A1 留下的机制问题——独立 CUSUM 能新增检出，且给出了
  新增的来源分解（SS 5 个真新增；OB 5 个真新增 + 19 个后移）。
  这是一次可复用的负结果，不是“再调一次阈值”。
- 负面：检测仍不可产品化；路线 A 的 A3 一次性 holdout 不启动；
  SS/OB 两套 dev 没有共同合规配置。
- 记录：AC-7 的 3σ 检测参照在本仓库不存在（3σ 只有定位排序器），
  该子句不可计算；报告的 AC-7 按 v2 参照判定，已显式披露。
- 后续：若继续路线 A，必须另立契约，先证明新机制能同时改善
  “新增检出”与“误报/覆盖”的兑换率；不能在 A2 网格上继续挑参数，
  也不能提前碰 TT/rep 4–5。
