# 对外面：术语双轨、双向门闩、覆盖范围声明

状态：accepted（2026-10-19）

上下文：这个项目的术语是**为精确而生的**——`docs/CONTEXT.md` 花了整段论证"澄清不是拒答"、
`_Avoid_` 逐条记下被否掉的近义词。问题不在术语本身，而在**它漏到了不该出现的地方**：页面上的
`⚡ 只读行动契约`、README 首屏的黑话、评审者第一眼看到的就是内部行话。实测出现次数（排除
`_archive`/`target`）：**行动契约 51 次 / 21 个文件**、变异验证 62 / 27、单飞 28 / 16、
指纹 224 / 58——而且**没有任何一道门闩管过文案用词**（CI 里只有 `provenance.py`、`doc_numbers.py`、
`check_panel_contract.sh` 三道"从产物现算"型门闩）。术语通胀是自己长出来的，没有一处是被拦下的。

决策：**术语双轨制 + 双向门闩 + 覆盖范围声明。**

1. **双轨**：canonical term 留在 `docs/CONTEXT.md`、`docs/adr/`、`OPS.md`、代码注释、审计列名与
   SSE 帧键；**对外面**用朴素工程词。每条 canonical term 在 `CONTEXT.md` 里用一行 `_对外_: …`
   登记别名（没有别名的写"无对外别名"）。
2. **对外面 = `README.md` 全文 + 两个 HTML 剥离 `<script>`/`<style>` 后的可见文本**。理由：只有
   这两个面是"外人会读的面"。`OPS.md` / ADR / `CONTEXT.md` / 代码注释一律算**内部面**，canonical 照旧。
3. **别名表**（本 ADR 只登记第一批；后续按同一规则增补）：

   | canonical（内部） | `_对外_`（对外） | 备注 |
   | --- | --- | --- |
   | 行动契约 | 只读命令清单 | 见下面"驳回"第 1 条 |
   | 变异验证 | 安全回归测试（改坏必红、复原必绿） | 只收窄到"测了什么"，canonical 仍指**方法** |
   | 单飞 | 并发合并 | 与"指纹"是两件事，不得合并命名 |
   | 指纹 | 去重键 | 对外叙述用 |
   | 对照模式 | 权限隔离演练 | 不叫"沙箱"——它不是隔离环境，是同一页面的对照视图 |

4. **门闩双向，但承认反向是启发式**：
   - **正向（可机器判）**：对外面不得出现登记在 `_对外_` 左侧的 canonical 黑话词。词表**不手写**，
     从 `CONTEXT.md` 现取——登记一个术语就等于同时登记了它的禁用面。
   - **反向（启发式）**：对外面出现的**术语性强调**（README 的 `**…**` 短语、页面上的机制名标签）
     必须在 `CONTEXT.md` 登记过（canonical 或别名）。这条**宁可漏报不误报**：它挡的是"现造一个新机制
     名"，不是做全文风格审查。
5. **覆盖范围声明**：知识库边界必须**提问前可见**（覆盖的服务数 / 错误码数 / 语义块数 / 最近重建
   时间），**按调用者身份过滤**、**从语料现算**，走 `GET /api/v1/copilot/coverage`；拒答时给"最接近的
   标识符"导航（`done` 帧的 `near_miss`，只带 `service` + `error_codes`，不带 chunk_id / 面包屑 / 正文，
   零召回给空数组），并挂"怎么扩覆盖"的动作入口（既有 `POST /api/v1/copilot/feedback`）。

理由：

① **"推荐命令"这个名字被驳回**：它撞 `CONTEXT.md` 里「行动契约」的 `_Avoid_`——那里记的理由是
**"推荐/建议"会被读成模型生成的**，而这套系统最关键的性质恰恰相反：命令**逐字来自语料**，模型不写
命令。"只读命令清单"里"只读"是硬性质、"清单"不承诺建议，也不暗示系统替你执行。
② **"告警指纹与单飞 → 告警去重合并与并发抑制"被驳回**：这是把两件不同的事焊成一句话。**指纹**回答
"这两条告警是不是同一个问题"（身份），**单飞**回答"同一个问题的并发请求谁来算"（在途合并）。
合成一句，代码读者就看不出这是两条分开的机制。
③ **覆盖范围必须服务端算、按身份过滤**：清单本身就是**越权面**——给 `sre-acme` 列出 tenant-internal
的服务名，等于把语料边界泄给外部租户；而手写的清单就是下一个会漂移的文档数字（这个仓库已经为这类
漂移建了"每次现算"的门闩）。
④ **拒答导航只给标识符、不给内容**：一旦把低置信度的 chunk 内容摆出来，用户就会拿它当答案用，而系统
无法保证那几段不是**别的故障**的手册——那会直接作废"拒答"这个信号，而拒答恰恰是最贵的诚实性资产
（`误拒/漏拒` 那套度量就是围着它建的）。候选来自**已按身份过滤**的检索结果，且只带服务名与错误码，
这两类恰好就是覆盖清单本身要公开的东西，故**不新增越权面**。

备选与否决：

| 被否项 | 理由 |
| --- | --- |
| 整体改名（canonical 也换朴素词） | 21–58 个文件的替换 + 改协议键（`actions`）；而两个拟议新名本身更模糊（见理由 ①②）。 |
| 只改 README | 页面才是"真用面"，黑话留在页面上等于没改。 |
| 全仓禁用词表 | 会误伤 ADR / OPS / 代码注释——那里正需要精确词。 |
| 页面静态写"支持 51 个错误码" | 必然漂移，且不按身份过滤（`sre-acme` 不该看到 tenant-internal 的服务名）。 |
| 拒答时给低置信度内容候选 | 见理由 ④。 |

后果：

- **门闩进 CI**：新增 `scripts/check_public_copy.py`，挂在既有的文档门闩 job 上（与 `provenance.py`、
  `doc_numbers.py` 同处）。
- **退化信号（要盯）**：如果这道闸开始产生"为了过闸而改写的奇怪句子"，说明它变成了形式主义，
  **应当降级为人工纪律**（删掉门闩，只留 `_对外_` 表）。这条写在这里，是为了让将来的人有据可依地
  把它拆掉，而不是继续喂它。
- **`_对外_` 表是单一事实源**：它同时承担"对外别名登记"与"门闩词表来源"两个职责——新增机制时
  忘登记，反向断言会提醒。
- **协议面不因术语而变**：`actions`、`refused`、`gate`、`near_miss` 这些帧键一律用 canonical 语义命名，
  不跟着对外别名走（对外文案解释它们，不改它们）。

相关：ADR-0017（行动契约）、ADR-0020（排障台，`refused`/`gate` 的来历）、ADR-0021（统一工作台，
页面可见文案是本次改写的对象之一）、ADR-0009（诚实性红线，覆盖范围声明是它的延伸）。

## 注记（2026-10-19 落地实测）

决策 5（覆盖范围声明）**已实现并活体验证**；决策 1–4（术语双轨与双向门闩）的**门闩与 README 全文
清扫当时未落地**（归 Step 5，见文末「注记（2026-10-19 Step 5）」）——本轮只把页面可见文案改成朴素词（`⚡ 只读命令清单`、
`权限隔离演练`、`安全回归测试`），**README 全文的措辞清扫刻意没做**：扫一半会留下两个口径，
不如一次性原子替换。下面记的是实现里才撞出来的东西。

**协议面形状（正文没写、评审会问的一处不一致）**：`near_miss` 是**候选组**的数组，不是扁平的
标识符列表——`[{"service": "...", "errorCodes": [...]}, …]`，且组内键是 **camelCase**
（Jackson 直出 `AnswerPayload.NearMiss`），而帧里其余键全是 snake_case。**有意保留**：这层
形状一一对应"某次检索命中里带出的标识符"，客户端拿到的分组就是检索的分组；改成扁平数组会让
"这个错误码属于哪个服务"这条信息在协议上消失，而它正是用户下一步要填进输入框的东西。
改键名的代价（缓存回放/审计侧要跟着动）大于收益，故不改。

**`facets_truncated` 为什么必须存在**：ES 的 `terms` 聚合在 `FACET_SIZE=1000` 处截断，
**截断不报错**——不显式带这个标志，覆盖范围就会在语料长大后静默少报服务/错误码，
而那正是"边界声明"最不能失真的地方。标志为真时页面写「⚠ 分面已截断」，把"我可能没列全"说出来。

**`built_at` 取不到就 `null`，绝不 `System.currentTimeMillis()`**：它的真值来自读别名指向的
物理索引 `settings.index.creation_date`；读不到时给当前时间是**把"不知道"伪造成"刚刚重建"**，
与 ADR-0009 诚实性红线直接冲突。`null` 时页面渲染"未知"。

**`identityFilters` 抽成单一事实源**：覆盖范围与检索必须用**同一份**身份过滤条件（tenant term +
`auth_level` range lte），否则"我告诉你边界是 A、检索却按 B 过滤"——这类偏差在页面上完全看不出来。
故把它从 `EsSearchService.search()` 里提成 `public static List<Query> identityFilters(tenant, authLevel)`，
两处共用（含 `tenant` 空值 fail-closed 的行为）。

**两个由单测抓出来的 ES 客户端坑（都已在代码注释里留档）**：

1. ES Java 客户端**总是**发 `typed_keys=true`，响应聚合键是 `sterms#services` 而不是 `services`——
   按字面量取键会永远拿到空聚合。现按 `endsWith("#" + name)` 匹配。
2. `GET /<index>` 返回的 `settings.index.creation_date` 藏在**内层**：客户端的 `IndexSettings`
   是自指的（`op.add(Builder::index, IndexSettings._DESERIALIZER, "index")`），取值要探两层。

**探针刻意不锁预设产额（被否的方案）**：`offline/preset_probe.py` 对每个预设只断言
`gate`（精确）+ 命令条数**有无**，不锁具体条数。被否的方案是逐条锁死（3 / 0 / 2）——实测
`MySQL 连接池耗尽` 3 条、`订单创建超时` 2 条、`支付网关 502` 0 条，看着很"可断言"，但产额被
`final-top-k: 3` 卡住，锁死会让探针随语料扰动假红。`支付网关 502` 那条**必须为零**是唯一的例外，
因为它是"命中但引用集无可执行围栏"的诚实零命令样本，页面不得假装有——那是个**承诺**，不是产额。

**顺带修掉的一处陈旧文档数字**：`doc_numbers.py --check` 现算 **23 条数字 / 37 处引用**，
而 README 正文写的仍是 36——这处 prose 数字**不在门闩管辖内**（它是描述门闩自己的话），
已按现算值改为 37。这类"描述门闩的话没人管"的漂移，登记在此备查。

**门禁与活体复核**：`check_panel_contract.sh` 四层一致；`demo.sh` 全 PASS；`mvn -B test`
**263/263**；`pytest offline/tests/` **304 passed**；`doc_numbers.py --check` / `provenance.py --check`
通过；`preset_probe.py` live **27/27 PASS**（4 次 chat 实调，预算 6）。浏览器实测（Playwright，
1440×900 / 390×844）：覆盖范围摘要与展开、点标识符回填、拒答导航（5 个候选 + 上报缺口按钮 → 审计
`ev="feedback"` 落地 `{"fp":"b911…","verdict":"down","note":"覆盖缺口：今天天气怎么样"}`）、
澄清态不渲染 near-miss 块、窄屏无横向溢出，全部正常。

## 注记（2026-10-19 Step 5：门闩与 README 清扫落地）

决策 1–4 落地了。记的是实现里才定下来的取舍。

**正向门闩（硬闸）**：`scripts/check_public_copy.py` 挂在 CI 的 `provenance` job（与 `provenance.py` /
`doc_numbers.py` 同处）。词表从 `CONTEXT.md` 的 `_对外_` 行**现取**（不手写），解析为空即报错
（空转门闩比没有门闩更危险）。当前解析出 6 条：行动契约→只读命令清单、变异验证→安全回归测试、
单飞→并发合并、指纹→去重键、对照模式→权限隔离演练、存储模式→零依赖试跑。

**完备性（决策 1 的第二半，同属硬闸）**：每条 canonical term 都要有一行 `_对外_: …`——没有对外别名
就写 `_对外_: 无对外别名。`。落地时把 39 条缺行的术语补齐（marker 统一插在 `_Avoid_:` 之前）。
为什么值得闸：没有它，就分不清"这条术语是**有意**不设别名"还是"**忘了**登记"，而 `_对外_` 表是
别名登记与门闩词表**共用**的单一事实源。

**一处对决策 2 的加严（有意）**：正文把对外面定义为"剥离 `<script>`/`<style>` 后的可见文本"。落地时
改为**只剥 `<style>`、保留 `<script>`**——面板的用户可见标签（"在途合并组" / "去重键"）由 JS 字符串
字面量渲染，整段剥 `<script>` 会把页面上的机制名放行，与决策 4 自己写的"页面上的机制名标签"自相矛盾。
canonical 词全是中文、代码标识符全是 ASCII，故不剥 script 不引入误报；代价（脚本 / HTML 注释里的
canonical 词也算违规）如实登记在 OPS §15。

**反向（决策 4 的启发式）落地为只报不闸**：实测严格过滤（纯中文 3–8 字、排除功能字）在现 README 上
仍给出 8 处候选（告警风暴 / 模型依赖 / 指令幻觉 / 零泄漏 / 词法哈希 / 排障台 / 运行面板 / 排障台旧地址）。
把它们做成硬闸就会逼出"为过闸而改写的奇怪句子"——正是本文后果段点名要避免的失效方式。故反向输出
`INFO`、不影响退出码。**这是对"门闩双向"的一处收窄**，理由与后果段一致。

**README 全文清扫（原子替换）**：canonical 词在 README 的 27 处（行动契约 11 / 指纹 8 / 变异验证 6 /
单飞 1 / 存储模式 1）全部换成别名；顺带把 `_Avoid_` 里的"变异测试"也换掉（它不在正向词表内，但同属
内部行话）。标题 `## 🧪 测试体系与变异验证` 改为 `## 🧪 测试体系与安全回归测试`，四处锚点链接同批更新。

**判据极性**：`offline/tests/test_public_copy.py` 15 例——对**每一个**登记词逐一注入 README 必须红
（漏一个 = 那条词表是死的）、HTML 可见文案 / script 标签 / 第二个 HTML 三面各一例、`<style>` 不算
对外面（边界）、空登记表报错、对外面缺文件报错、**抹掉一条 `_对外_` 行即红（完备性）**、反向只报
不闸、登记过的别名不进 `INFO`。

**门禁与活体复核**：`mvn -B test` **294/294**；`pytest offline/tests/` **319 passed**；
`check_panel_contract.sh` / `doc_numbers.py --check` / `provenance.py --check` /
`check_public_copy.py --check` 全绿；`preset_probe.py` live **27/27 PASS**。
