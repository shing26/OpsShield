# ADR-0033：事故责任流转（转交 / 我的 / SLA 提醒）

- 状态：已采纳（2026-11-22）
- 相关：ADR-0005（审计）、ADR-0032（事故持久化与分配边界）、ADR-0022（memory 模式）、
  契约 [plans/incident-responsibility-accept.md](../plans/incident-responsibility-accept.md)

## 背景

ADR-0032 把事故变成了服务端对象，但只回答了"这条单现在归谁"：`owner` 是就地覆盖，
查不出"谁在什么时候把单子交给谁、为什么"；左栏只有"本租户最近 60 条"，值班人无法只看
自己负责的单；优先级只是标签，没有时限与超时提醒。

本切片补三件事：**转交事实**（append-only）、**服务端「我的」筛选**、**按优先级派生的 SLA**。
推送（IM / 邮件 / 浏览器通知）明确不在本切片：它需要先定"谁收、频率、静默期"。

## 决策

1. **转交是唯一写入口**。新增 `POST /incidents/{id}/transfer`，body `{toOwner, reason}`。
   `PATCH owner` 保留兼容，但内部走同一个 `IncidentStore.transfer` 事务入口：带旧 `owner`
   的条件更新 + 追加 `incident_assignments` 一行，二者同成功同失败。
   `reason` 为空归一为 `—`，超过 200 字 400；`toOwner` 必须是本租户启用用户（否则 400）；
   与当前 owner 相同 409（不做无意义写入）。
2. **转交历史只从 append-only 表读**。`GET /{id}/assignments` 倒序最多 50 条。
   客户端时间线是整段覆盖写的快照，并发下会丢行，**禁止**拿它当责任凭证（ADR-0032 已记该边界）。
3. **授权不新增角色**。沿用 ADR-0032 的责任动作授权：`created_by` / 当前 `owner` /
   `role=platform`；越权 403 并落 `ev=incident action=transfer outcome=forbidden`。
   跨租户读转交历史一律 404，与 `GET /{id}` 同口径。
4. **「我的」在服务端筛选**。`GET /incidents?mine=true` 按 `owner = 调用者 sub` 过滤，
   `?status=open|closed` 可叠加；无参数行为与历史版本完全一致。前端进入「我的」时
   **必须关闭 `refreshIncidents()` 的 localOnly 回填**：刚被转交出去的本地单已不属于调用者，
   用缓存补回来会让筛选形同虚设。
5. **SLA 由优先级派生，阈值全走配置**。`opspilot.incident.sla.*`：
   `p1-minutes=30 / p2-minutes=120 / p3-minutes=480`，空优先级不设时限。
   `due_at` 在创建与改优先级时重算；清空优先级则 `due_at=null`。
   配置由 `@EnableConfigurationProperties(IncidentSlaProperties.class)` 显式注册——
   record 的构造器绑定不能靠 `@Component` 扫描（会退化成按参数自动装配并启动失败）。
6. **SLA 提醒是状态跃迁，不是每次扫描都写日志**。`@Scheduled` 默认 60s（可配）扫描未结单事故：
   `now > due_at - 20% 窗口` → `due_soon`，`now > due_at` → `breached`。
   迁跃只前进不后退；`transitionSla` 带旧状态做条件更新，只有更新成功的线程写
   `ev=incident action=sla outcome=due_soon|breached`。同一状态不重复落审计；
   已结单事故由 SQL 的 `status = 'open'` 排除。重开或改优先级时 Service 显式把状态重置为 `ok`。
7. **界面沿用既有视觉语言**：左栏增加「我的」，右栏事实区增加「时限 / 剩余」，
   `due_soon` / `breached` 复用既有 warn / err 语义色；页头增加「转交」弹层
   （负责人 + 理由 + 最近 3 条历史），失败必须 toast 明示。不引入新依赖。

## 后果

- **单实例进程内扫描**：与 SingleFlight 同一边界，不加分布式锁。多实例部署会重复扫描；
  条件更新保证同一状态只落一条审计，重复扫描最多是空转。需要多实例时再引入租约或选主。
- **扫描是唯一一处跨租户读**：系统任务没有调用方 JWT，先枚举"有开口到期单据"的 tenant 键，
  随后每张单的读取、条件更新与审计都带该 tenant。它只读 tenant 列，不返回业务数据。
- **`sla_state` 是服务端派生值，前端不重算跃迁**：前端只按 `dueAt` 现算"剩余 X 分"用于显示，
  阈值不落前端。这样改配置只需重启服务端，不需要重新发布页面。
- **迁移兼容**：V6 只新增 `incident_assignments` 与两个可空/有默认值的列，旧代码读不到新列不阻塞启动；
  回滚 `git revert` 本分支即可。自增主键用 `GENERATED BY DEFAULT AS IDENTITY` 而非
  `AUTO_INCREMENT`——H2 的 PostgreSQL 兼容模式（测试库）不认后者。
- **PATCH owner 的审计仍是 `action=assign`**：兼容路径不改变既有动作词表；只有显式转交
  才落 `action=transfer`。两者写入的责任事实相同（`reason=—` vs 用户填写）。

## 备选方案

- **把转交写进客户端时间线**：零 DDL，但时间线是整段覆盖写，并发会丢行，且无法按事故查询——
  与"责任可追溯"直接冲突，否决。
- **SLA 在请求时计算**：没有请求的时间段里状态不会变，"超时提醒"只在有人刷新时出现，
  等于没有提醒，否决。
- **分布式锁 / 多实例选主**：当前部署形态是单实例；为一个尚不存在的部署形态引入协调依赖，
  成本高于收益。写进后果，等真的多实例时再做。
- **本切片顺带做 IM/邮件推送**：收件人、频率、静默期都未定义，塞进来会把一个可验收的
  责任切片变成无法收口的通知系统，明确推迟。
