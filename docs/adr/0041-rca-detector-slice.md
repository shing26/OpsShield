# 0041. RCA 检测器切片：先离线证伪，不接产品面

- 状态：Proposed（待 Lead 签收）
- 日期：2026-11-26
- 契约：`plans/rca-benchmark-accept.md`（FROZEN）
- 证据：`offline/rca/reports/M2-report.md`

## 背景

网关当前只覆盖「知识检索 + 只读护栏」，看不见系统遥测。要往「快速定位」走，
必须先回答一个可证伪的问题：**在公开故障数据上，我们的定位方法是否真的比简单基线好？**

## 决策

1. 新增 `offline/rca/` 研究切片：外部数据（RCAEval RE1-OB）、固定划分、4 个基线、
   逐 case 结果与 provenance。它是**离线工具**，不改产品运行时。
2. v1 方法 `topo-first`（材料性下限 + P90 持续性 + 拓扑扣减 + 时相加权）**不接入网关**。
   测试集上没有非回归证据：Top-1 +2pp（p=1.00）、Top-3 −6pp；delay 故障 100%→20%。
3. 保留其作为**资源故障流水线**的定位臂：配资源型在线检测器时，条件 Top-1 93.3%、
   端到端 56%（漏检与误报都记失败）、中位检测延迟 14s。这是目前唯一有数据支撑的可用组合。
4. v2 必须另立契约，且满足：
   - 双检测臂（资源 + SLI）覆盖 delay/loss；
   - 定位按故障类型自适应；
   - 选参加入分故障非回归约束；
   - 在 RE1-SS（新系统）做外部验证，RE1-OB 测试集不再参与选参。

## 否决项

- **直接接进 `ChatOrchestrator` / 告警增强**：测试集无增益，delay 类型明确退化；
  接了会把一个未证实的先验塞进产品路径。
- **用 RE1-OB 测试集继续调参**：一次测试集已经用掉；再调就是自评。
- **只报聚合 Top-1**：dev 上聚合 +9.4pp 掩盖了 delay −60pp；后续选参必须报分故障。
- **把 3σ 当弱基线**：它是本数据上最强基线（测试集 68% / 92%），
  任何新方法必须先过它这一关。

## 后果

- 正面：有了可复现的对照组、数据 provenance、检测延迟口径；负面结论本身阻断了
  一次无证据的产品集成。
- 负面：`offline/rca/` 引入 pandas/pyarrow 依赖，只能活在隔离 venv；
  不进入 `offline/requirements-dev.txt` 或运行时。
- 负面：契约字面要求的 MAD 基线在本数据上退化（test Top-1 0.020），
  说明"robust-z"不是无条件的稳；后续基线选择需按数据方差结构做 sanity check。
- 待办：v2 契约、RE1-SS 适配（Sock Shop 拓扑）、SLI 检测臂。
