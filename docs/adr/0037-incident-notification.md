# 事故单通知：站内持久化优先，群机器人外发可选且提交后异步

## 上下文

ADR-0033 让 `owner` 变更成为可追溯事实，`IncidentSlaScanner` 也会把
`ok → due_soon → breached` 写成审计跃迁。但这两件事都只改数据库：

- 被转交的人不刷新列表就不知道单到自己名下；
- SLA 临期/超时只改 `sla_state`，没有任何面向人的提醒；
- 评论未读是 `sessionStorage` 水位（ADR-0034），换设备或换班即丢；
- 值班人无法回答"现在有几条与我有关"。

同时必须承认现实约束：`users` 表没有邮箱、手机号或 IM open_id。
猜用户身份去私聊既不可验证，也会把通知变成新的权限面。

## 决策

新增**站内通知**：一张按 `(tenant, recipient)` 隔离的派生表，通知只带定位信息
（事故 ID、标题、优先级、时限、事件类型），不复制 query、诊断正文、评论正文或引用片段。

1. **同一事务**：通知行与事故变更（转交 / PATCH owner / SLA 跃迁 / 重开）共用调用方事务。
   事故回滚则通知零行；不会出现"事故改了没人知道"或"通知发了事故没改"。
2. **去重**：唯一键 `(tenant, recipient, dedupe_key)`，冲突按正常分支吞掉。
   - `assigned:<incidentId>:<toOwner>:<minuteBucket>`
   - `sla:<incidentId>:<state>`
   - `reopened:<incidentId>:<minuteBucket>`
   - `minuteBucket = epochSecond / 60`，跨分钟边界最多两行；不为绝对去重引入分布式锁。
3. **收件人**：`assigned` 只发新负责人；`sla_*` / `reopened` 发当前负责人 + 创建人；
   操作人本人不收；收件人必须在本租户且启用，空负责人只发创建人。
4. **外发可选且默认关闭**：`opspilot.incident.notify.webhook-url` 为空即不发。
   配置后只在事务提交后入有界队列（默认 256），单线程单次尝试、连接/读取各 3s、不重试、
   不阻塞请求线程；队列溢出丢弃并计数，绝不回落到调用线程。
5. **静默期**：默认 `22:00–08:00`（`Asia/Shanghai`，可配）只约束外发，不约束站内记录；
   非 P1 记 `suppressed=quiet_hours`，P1 不受限。"没发"必须可查。
6. **不做个人 IM**：本切片不新增邮箱/手机号/open_id 字段，也不猜身份；个人私聊需先补
   联系方式与用户同意，另开切片。同样不做邮件、短信、Web Push、失败重试与多实例去重。

## 否决项

- **把通知塞进 `incidents.timeline_json`**：那是整段覆盖的状态快照，不是按收件人隔离的事实；
  也回答不了"谁读过"。
- **在请求线程或事务内直接发 webhook**：慢上游会拖长转交接口，发送失败还可能回滚事故变更。
- **用 Redis/消息队列承担通知**：单实例范围内引入第二套存储与投递语义，收益不抵运维面。
- **按用户名猜 IM 身份**：不可验证、会误发到他人，且新增隐私与权限边界。
- **为绝对去重加分布式锁**：分钟桶 + 唯一键已满足"同一事件同一人一行"；锁只增加阻塞面。

## 后果

- 通知是派生数据，`git revert` 后旧代码不读该表；V10 只新增一张表，既有迁移不变。
- 前端铃铛在接口 404 时隐藏，灰度/回滚期不阻塞事故单页；30s 轮询 + 聚焦刷新。
- 外发失败只记 WARN 与 `aiops_incident_notify_webhook_total{result}`，不影响接口与事务。
- 多副本部署下每个副本都可能入队一次（与 ADR-0036 的调度边界一致）；当前单实例验收成立。
