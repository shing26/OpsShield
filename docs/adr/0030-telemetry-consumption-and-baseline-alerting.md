# ADR-0030：遥测消费与统计基线预警——谱系表 ①② 的边界修订

日期：2026-11-11 ｜ 状态：accepted ｜

## 背景

事中链路已经闭环：告警接入 → 削峰 → 检索 → 可溯源建议。缺口在**事前**——系统只能在静态
阈值被击穿、或上游告警系统判定异常之后才知道出事。"这阵子不太对"这件事，今天没有任何
代码在回答。

ADR-0029「后果」段已经把方向预支给本 ADR，原文：

> 未来故障预测（Prometheus 拉取面）以插件形态进入，不动底座。
> 谱系表联动：故障预测若立项，需另行 ADR 修订 `docs/positioning-aiops.md` 谱系表
> ①②行（"永久非目标"→"不自建采集，消费既有时序"），本 ADR 不预支该修订。

三个事实决定了这件事的成本很低、方向很窄：

1. **遥测已经在栈里**。`ops/alerting/prometheus.yml` 抓宿主 8081 的 `/actuator/prometheus`
   （ADR-0016），retention 默认 30d。缺的不是数据，是**读它的判定**。
2. **投递接缝已经存在**。`offline/alert_delivery.py`（ADR-0024）已经提供来源无关的
   `AlertDelivery` / `DeliveryPolicy` / `Gate` / `QuotaSnapshot`；`offline/alert_producer.py`
   （ADR-0011）是"读既有面 → 判定 → 打进既有 `/chat/stream`"的现成范例。
3. **谱系表 ①② 的"永久非目标"是一句会被证伪的断言**。它当时的证据是"全仓无检测算法路径"
   与"术语表无此词条"。一旦落地消费侧能力，这两条证据同时失效——留着不改就是**宣称失实**，
   比不做更糟。

## 决策

### (a) 不自建采集：只经 Prometheus HTTP API 读既有时序

不新增 scrape 配置、不建指标库、不做拓扑采集。唯一的数据入口是
`/api/v1/query_range`（需要一段历史求基线，instant query 不够），出口经
`localapi.assert_local`（仅 http + 环回 + 解析后 IP 仍环回）。**别的部署里 Prometheus
抓什么，这里就能读什么**——这正是"插件"的含义：底座不认识指标，只认识一个 URL 与一条 PromQL。

采集平台是另一个产品（容量规划、存储、标签治理、高基数、远程写），本系统不碰。

### (b) 可解释统计基线：中位数 + MAD，双阈值，退化情形显式

基线 = 历史窗口内样本的**中位数** `med` 与**绝对中位差** `MAD = median(|x − med|)`；
偏离度用标准 modified z-score `z = 0.6745 · (x − med) / MAD`（Iglewicz–Hoaglin 常数）。

**为什么不是均值 + 标准差**：线上时序的方差本身会被尖峰抬高——用标准差当尺子，异常越大
尺子越松，恰好在需要它的时候失灵。MAD 的崩溃点是 50%，一个尖峰动不了它。

**为什么不用黑盒模型**：告警的价值在于"值班人敢据此行动"。一条说"模型认为异常"的告警无法
被复核，误报时也无法反驳。本实现的每条预警正文自带当前值、基线中位数、MAD、偏离 σ、绝对差、
样本数与窗口——**读者可以手算复算**。

**双阈值**：`|z| ≥ z_threshold` **且** `|x − med| ≥ min_abs_delta`。单靠 z，一条噪声极小的
平稳序列会因为 0.001 的抖动报警；单靠绝对差，一条本身就在大幅摆动的序列会永远报警。

**MAD = 0 必须显式处置**：序列恒定或近恒定时 `MAD = 0`，z 无定义。实现走"仅绝对差 +
`min_abs_delta`"分支，并在台账与告警正文标 `degenerate_mad_zero`。**不除零、不静默告警、
不静默放过**——这是本决策唯一点名要求实现的退化分支，因为它是最容易被"顺手"写成
`if mad: ... else: pass` 的地方。

### (c) 预警走既有编排链：不新增后端端点、指标与权限维度

命中后以 `{"query": <自解释文案>, "source": "alert", "service": …, "env": "local"}` POST 到
既有的 `/api/v1/copilot/chat/stream`。冷却（按 `规则:服务`）、每小时上限、配额保留线、
dry-run 四道闸门复用 `AlertDelivery`。

这条决策的意义不是省事，而是**让预警继承整条链路的构造保证**：它自动获得指纹去重、
Single-Flight 收敛、降级时的静态 SOP 直出、逐字出口护栏与溯源 refs。若新开一个
`/api/v1/alerts/predictive` 端点，上述每一条都要重新实现并重新验收——而它并不会因此变得更好。

告警文案**刻意不带错误码**：既有三条业务规则带错误码（走精确符号快路径），这条纯语义，
形成对照。混粒度是 `ops/alerting/rules/opspilot.yml` 文件头已写明的刻意设计。

### (d) 插件形态：落在 `offline/`，底座零改动

实现是 `offline/predictive_alerts.py`，一个 stdlib-only 的进程，与 `alert_producer.py` 同构。
**不改任何 Java 代码**（`git diff -- src/main/java src/main/resources` 为空是验收条件）。
按 ADR-0029 决策 1 的分层判据，它属于领域插件：它提供的是"哪些指标值得盯、偏离多少算异常"
这类领域内容，而投递机制、权限、审计、缓存全部来自底座。

这也让 ADR-0029 的 rule-of-three 得以遵守：本任务是"执行闭环"之后的第二个真实用例，
**只复用接口、不提取新接口**。

### (e) 谱系表 ①② 修订：从"永久非目标"到"消费侧已覆盖"

`docs/positioning-aiops.md` 谱系表：

- ① 遥测采集 → **已覆盖（消费侧）**，采集仍非目标。
- ② 异常检测 → **已覆盖（统计基线预警）**，ML/根因仍非目标。

口径一句话：**不自建采集，消费既有时序；统计基线预警属已覆盖的消费侧能力**。
同步修订的还有：`### A. 永久非目标` 的 ①② 两行（移出并加修订注）、`### D. 已兑现` 新增一行、
第 18 行一句话口径、第 104 行重开条件段；`docs/ops/roadmap.md`「明确不做」第 1 条加修订注
（原文保留）；`OPS.md` §5「处置闭环」行的注记；`docs/adr/0013` 与
`docs/qa/2026-10-22-ops-readiness-review.md` 各加一行修订注（历史断言不改写）。

## 备选与否决

| 备选 | 否决原因 |
| --- | --- |
| 做采集平台 / 指标库（Prometheus 之外的 scrape、存储、拓扑） | 那是另一个产品：容量规划、高基数、远程写、标签治理的债务与当前时间预算冲突；本系统的缺口在**判定**，不在**采集** |
| 上黑盒 ML 异常检测（孤立森林 / LSTM / 外部模型推理） | 不可复核：误报时值班人无法反驳，漏报时无法定位。且引入第三方 ML 依赖违反"stdlib-only、零外部依赖"的离线面口径 |
| 新增后端告警端点（`/api/v1/alerts/*`） | 会让预警**绕开**现有的指纹去重、Single-Flight、降级直出、逐字护栏与溯源合同；上述每一条都要重做一遍验收，收益为零 |
| 把预警升级为自动处置（命中即执行 runbook） | 撞 ADR-0013（不引入决策循环/写动作）与谱系 ⑤（处置闭环按债务闹钟表挂起）。**统计偏离不是根因**，据此自动执行等于把猜测变成动作 |
| 用趋势外推/预测模型替代基线偏离 | 本 ADR 只承诺"相对自身历史异常"，不承诺"算出未来值"。预测需要模型与回测口径，属另一个决策，见下节重开条件 |
| 复刻一份 `alert_producer.py`（复制粘贴而非复用） | 冷却/预算/配额/登录归因四道闸门会在两份实现里漂移；ADR-0024 的存在就是为了避免这件事 |

## 明示未做的边界

本 ADR **不**承诺、也不实现：

1. **趋势外推 / 预测模型**——不做"未来 N 分钟 P99 会到多少"。基线是"与自身历史比"，
   不是"预测未来值"。
2. **根因分析**——预警只说"偏离了"，不说"因为什么"。原因仍由检索链路与人生成。
3. **自动处置**——不执行任何写动作。

**重开条件**（按行标题引用，不写裸行号，理由同 ADR-0013 决策 3：行号会随 §5 加行静默偏移
且无门闩报警）：上述三项的重开条件收在 `OPS.md` §5 债务闹钟表的
「处置闭环（对目标系统的自动执行/自愈）」行注记里——与该项"产品方向转执行 + 可审计执行通道"
同款写法：到点才立项，不预防施工。

## 后果

- 正面：事中链路之外补上了事前的一层；谱系表 ①② 的断言与代码一致，不再有"宣称失实"；
  `offline/` 侧多了一个可独立运行、可 `--dry-run` 的只读进程；ADR-0029 预支的方向兑现，
  且底座零改动（插件形态得到一次真实检验）。
- 代价：新增一个需要值班人理解的判定式与一份运维文档；基线是"自身历史"而非跨实例基线，
  冷启动与业务形态变化期会失真；Prometheus 不可达时**宁可静默也不伪造读数**——这是刻意的
  fail-closed，代价是"它没报警"不等于"一切正常"。
- 文档门闩：ADR 总数 29 → 30，README 与 `docs/repo-map.md` 的 `adr_count` 引用随本篇合入同步改
  （`offline/doc_numbers.py` 现算比对，改字是被门闩要求的）。
- **遗留（如实登记）**：`docs/adr/0029-reuse-boundary-trust-base-vs-domain-plugins.md` 第 78 行
  仍引着修订前的措辞「①②行（"永久非目标"→…）」。该文件不在本任务的 Allowed paths 内，
  **本 ADR 不改它**；该行属"预支条款的历史表述"，其兑现即本篇。若后续要消歧义，
  需单独授权一次 doc-only 修订。
