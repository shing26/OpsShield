# 跨指纹 incident 关联：事故边界由上游定义，复用 X-Trace-Id

上下文：AIOps 谱系表 ③（告警降噪/事件收敛）写的是"已覆盖（同指纹域），**跨指纹 incident 关联未覆盖**，
该边界已入债务账并带触发线"。触发线要求"真实告警流中出现同一根因、多措辞/多服务的告警且人工归并成本
可测"——Alertmanager 接入后该前置已满足（真实外部告警流存在，见 ADR-0011/qa §1-§2），而实测确认
**同一根因的多条告警天然是多个指纹**（qa 台账 §3.1）。于是"跨指纹"要做成什么样，成了必须回答的决策。

决策：**只做关联，不做归并**。一次事故的边界**由上游定义**——它就是 Alertmanager 按 `group_by` 划出的
一个告警分组的一次生命周期；本系统不重新发明"哪几条告警属于同一次事故"这层判断（同立场：谱系表 ②
把"何时算异常"永久让给上游）。事故的关联键 = `am-` + `SHA256(groupKey + "|" + 组内最早 startsAt)` 取摘要
前 128 位，随 **`X-Trace-Id`** 请求头送到网关、落在审计行 `trace_id`。配套两行配置改动：
`group_by: ["job"]`（去掉 `alertname`——带着它时分组与单条告警同粒度，等于没关联）与
`group_interval: 1m`（缺省 5m 太贵）。

理由：① 缺口的原始措辞是"跨指纹目前仍靠**人读**告警文本"，缺的是可读性不是省调用；② 复用 `trace_id`
使产品面**零改动**（该头是过滤器层的，覆盖全部四个面，不碰任何 DTO），且审计面本来就有这一列；
③ 身份要拼 `startsAt` 是因为 `groupKey` 是**路由桶 id**而非事故 id——它不含时间维，同一条规则下周再 fire
会落回同一个桶，直接当事故 id 会把两次事故并成一次；组内最早 `startsAt` 在组生命周期内稳定，组重建自然换新。
④ 键必须是 `[A-Za-z0-9_-]{8,64}`（`X-Trace-Id` 的词法约束），而 groupKey 原文形如
`{}:{alertname="X", job="y"}`——含 `{}":,`，直接透传必然 400，故只能派生；`am-` 前缀是自描述用的。

备选与否决：**归并（N 条 → 1 次检索生成、1 个答案）**——要先回答"拿哪条告警的文案当 query"，本仓已否决过
一次（桥刻意逐条摊平：合并会把 N 条压成一个指纹，测的就成了拼串手艺），且"N 条共用一答案"的对象成员会随
时间进出，缓存与单飞语义要重发明一遍，否决；**我们自己按标签派生事故**（如 `job`+集群标签）——把判定权
挪回本系统，与谱系 ② 的立场冲突，要额外论证才立得住，否决；**新增 body 字段 `incidentId`**——多一个字段、
多一列审计、多一份"它与 trace_id 什么关系"的解释，买到的能力与复用完全相同，否决。

后果（实测读数，qa 台账 §7）：同一事故的两条不同告警共享一个 `incident_id` 而各自有不同 `alert_id`
（关联成立、归并未发生）；代价是告警会等一个 `group_interval`——实测投递延迟 **57–59s**；且组更新会把
**全体成员**重发一遍（Alertmanager 载荷不是增量），桥不判重（既有取舍：重复必须真的打到网关），
实测那次重复命中 **L1**——这恰好是 ADR-0018 那层身份在真实流量上的回报。resolved 与 firing 是两种
告警身份，故 resolved 通知会各跑一次完整管线。**已知边界**：抑制规则（inhibit）决定"哪些告警根本不投递"，
被抑制的告警不会出现在事故里——那是上游的判断，不是丢数据。

**未实测边界（2026-10-19 code-review 登记）**：anchor 取本次投递 `alerts[]` **全体**的 `min(startsAt)`，
而正文的稳定性论据是"整个 group 每次重发都带齐全体成员"。若某成员在 group 生命周期内**先 resolved 并
离开 payload**，`min` 会抬高、`incident_id` 随之漂移，把一次事故拆成两段——§7.2 的边界判据只覆盖
firing 成员，这条路径未验。触发线：出现一次"同一次事故在审计面被 `am-…` 拆成两段"且被真人/QA 复现
（判据：能指出两条本应同组的 `trace_id` 与其成员交集）→ 立项把 anchor 换成不随成员进出变化的值。

相关：ADR-0003（单飞）、ADR-0011（自举告警源）、ADR-0018（告警身份，事故身份的另一半）；操作面见 OPS §13。
