# 定位：agent 的可信底座，不是第 4 个 agent

状态：accepted（2026-09-28，随《OpsPilot 完整系统化改进计划》同轮 grill 拍板）

上下文：作品集里有四个"进了 agent 矩阵"的项目（moa-gateway 开放 ReAct / ShopPilot 有界工具调用
状态机 / CodeCompass 网页端循环 / 本项目）。七维审计 v2 的 §5 把本项目摆在二选一前：写成 agent
项目，还是 agent 的可信底座。两条事实同时为真：

1. 本项目**确实有三处 agent 形状**——自举告警闭环（感知→上报→处置→停报）、降级状态机
   （`resilience/DegradationStateMachine`）、置信度门控 + 显式拒答（`ChatOrchestrator` 门控分支）。
   感知/决策/动作的分段与反馈控制回路都在，只是**判据是阈值与计数器，不是模型**。
2. 它的差异化恰恰建立在不引入 LLM 决策循环之上。

而这件事在此之前**只活在仓外**：`.workbuddy/memory/2026-09-17.md` 写了"反 agent"命题，但
`grep -rniE "反 ?agent"` 在仓内 **0 命中**；仓内已有的成文定位是 README 的 AIOps 谱系表与
"与朴素 RAG 的五条差异"——**对比轴是 RAG 与 AIOps 谱系，不是 agent**。定位散在记忆里，
第三方无法复核，这与本项目"承诺必须可核验"的整体立场不一致。

决策：

1. **定位＝agent 的可信底座**：把权限双硬过滤、溯源合同、风暴收敛、置信度门控、降级状态机
   当作"给上层 agent 兜底的那一层"。对外（投递材料 / 面试）统一用这个口径，**不并列成
   "agent 项目"的一格**。
2. **在仓内把它写下来**：README「与 agent 的关系」一节 + 本 ADR，使这条承诺可被外部逐句复核。
3. **不引入 LLM 决策循环 / tool-calling**。本条的重开条件**不新开触发线**，直接指向
   `OPS.md` **§5 债务闹钟表**的「处置闭环（对目标系统的自动执行/自愈）」行（按行标题引用，
   不写裸行号——行号会随 §5 加行静默偏移且无门闩报警）。
4. **边界声明**：只读式多步循环的上游（拓扑 / 指标类遥测）属谱系 ① **永久非目标**，故不单列。

理由（为什么是"底座"而不是"第 4 个 agent"）：

- **能到达的循环必然带写动作**——只读多步的上游被谱系 ① 永久非目标堵死，故"引入循环"这件事
  已被 §5 的 ⑤「处置闭环」覆盖。另开一条触发线＝造第二本账，与「长期记忆」开第二账被拒
  （撞 `OPS.md` §5.1「复盘 → 知识回灌」）是**同一类错误**。
- 四项目并列时，本项目最强的三处（双引擎权限硬过滤、逐字出口护栏 + 溯源合同、同指纹风暴收敛）
  在"agent 项目"这个筐里**反而不突出**——而它作为"底座"的稀缺性正是这些。
- 该定位同时满足两个目标：进了 agent 叙事（它是 agent 的必要下游依赖），又保住了不引入循环的
  唯一性。二选一的两边都不必牺牲。

否决项：

- **写成"第 4 个 agent 项目"**：与 README 谱系表的一句话口径（"做的是 AIOps ③④ 两个子域的
  网关入口层"）、以及 `docs/ops/production-readiness-2026-09-12.md` 的书面裁决
  （"不做任务规划/多步 Agent 循环——无此任务形态，会摧毁定位叙事"）正面冲突。
- **给底座加多轮会话态来"显得像 agent"**：撞 `ADR-0007` 的无状态检索语义声明。底座被多步调用
  需要的是**调用方关联键**（`X-Trace-Id`，见 ADR-0007 修订注），不是记忆——两件事在
  `RequestIdFilter` 的类注释里已分开写清。
- **写成"永久非目标"、不设重开条件**：与 §5 ⑤ 的析取项①"产品方向从建议转执行"自相矛盾——
  那条已经承认方向可能变；把实现形态写成永不重开，等于当场推翻自己的另一条账。

后果：

- 简历少一个 agent 项目计数；"会做 agent"的举证由 moa-gateway（开放 ReAct + HITL）与
  ShopPilot（有界状态机）承担。
- ADR 总数 12 → 13；README 的 ADR 计数由面二门闩（`offline/doc_numbers.py`）**现算比对**，
  改字是被门闩要求的，不靠人记得。
- 后续任何"给本项目加循环"的提案，先回答 §5 ⑤ 的两组析取项是否成立；两条都不成立即不立项。

> **修订注（2026-11-11，ADR-0030 合入时追加）**：本 ADR 正文的"谱系 ① 属永久非目标"
> 是 2026-10 的时态表述，**已被 [ADR-0030](0030-telemetry-consumption-and-baseline-alerting.md) 修订**——
> ① 改为**消费侧已覆盖**（只读 Prometheus 既有时序，不自建采集），② 落地统计基线预警。
> 本 ADR 的决策不受影响：**不引入 LLM 决策循环 / tool-calling** 的立场不变，"能到达的循环必然带写动作"
> 仍然成立——消费既有遥测是只读的，不构成循环的上游。原文按历史文档纪律保留不改。
