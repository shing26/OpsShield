# 告警回看使用键集分页，保留窗口内的老告警可被逐页读完

## 上下文

告警台账此前只有增量读取：`GET /api/v1/admin/alerts/recent?since=` 以 `last_seen` 水位
返回最新一批，面板再用 `S.alerts.length > 100` 直接截断。`since` 是「新告警水位」，
不是分页游标，因此：

- 保留窗口（默认 30 天 / 每租户 500 条）里的老告警没有任何读取路径；
- 100 条是硬天花板，用户无法继续加载；
- 排序缺少 `tenant`，同一 `last_seen` 且同名 `alertId` 分属两个租户时顺序不稳定；
- 两次轮询之间新增超过 `limit` 条时，`recent` 只返回最新一批，中间段既不展示也不会再被拉到。

## 决策

1. **新增端点，不改旧语义**：`GET /api/v1/admin/alerts/history?cursor=&limit=`；
   `/alerts/recent` 的入参、响应字段、limit 夹取与轮询语义零改动。
2. **键集（keyset）分页，禁止 OFFSET**。排序键为
   `(last_seen DESC, tenant DESC, alert_id DESC)`。`tenant` 进入排序只为消除并列，
   不是授权依据；端点仍是平台门禁，跨租户可见性不变。
3. **游标不透明**：`base64url(v1|epochMicros|base64url(tenant)|base64url(alertId))`，无 padding。
   时间取数据库回读行的 `Instant` 微秒值，不用毫秒截断——同一毫秒内的多行若只按毫秒比较
   会在键集边界丢行。内层段各自 base64url，避免 tenant/alertId 里的分隔符破坏格式。
   非法版本、段数、空段、长度越界（tenant>64 / alertId>128）一律 400；日志不记录游标原文。
4. **快照语义**：行在翻页途中被 `touch`（`last_seen` 前移）会移到第一页，可能不再出现在
   后续页；保留任务删掉的行也会消失。刷新即最新。这是键集分页对可变排序键的已知边界，
   不为它引入快照表或锁。
5. **与轮询的分工**：首屏走 `/history` 第一页并用 `max(lastSeen)` 初始化水位；
   之后轮询继续 `/recent?since=` 只拉增量。`recent` 返回 `truncated=true` 时，
   面板重载 `/history` 第一页并提示「新告警超过单次窗口，列表已刷新到最新」，
   不锁存「仅显示最近 N 条」的死胡同文案。
6. **前端上限 1000 条**：加载更多按 `(tenant, alertId)` 去重追加，不重排已加载页；
   到顶后按钮显示「已加载最近 1000 条，请用保留窗口缩小范围」。
7. **索引**：V13 只新增 `(last_seen, tenant, alert_id)`；全 DESC 排序可由该索引反向扫描满足，
   不新增排序列，不改 V1–V12。

## 否决项

- **`LIMIT ? OFFSET ?`**：深页越翻越慢，并发写入会重复/漏行。
- **给 `/alerts/recent` 加 `cursor` 双模式**：旧端点的水位语义会被搅在一起，
  旧客户端与轮询路径都要重新验证；新增端点把变更面留在增量侧。
- **毫秒精度的时间键**：同一毫秒的多行会在 `last_seen < ?` 处整批丢失。
- **把游标当授权凭据**：游标可被客户端改写，只能表达排序位置；tenant 的可见性仍由平台门禁决定。
- **为可变排序键引入快照表/分布式锁**：接受键集分页的快照边界，刷新即最新。
- **一次拉全量或无限撑 DOM**：客户端上限 1000 条；超出用保留窗口缩小范围。

## 后果

- 保留窗口内的老告警可被逐页读完；窗口之外不存在「永久历史」，这是保留策略的边界不是缺陷。
- `FlywayMigrationTest` 覆盖空库与已有库，并断言 V13 索引列顺序。
- 性能边界已登记：跨租户台账总量 > 50,000 行或 `/alerts/history` p95 > 200ms 时，
  再评估分区/归档或物化排序键；本切片不提前施工。
