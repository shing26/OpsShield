# 排障台：单次请求的协议面证据面，任意有效 JWT 可用，不读审计

状态：accepted（2026-10-18）

上下文：ADR-0009 立了面板 `/`（只读可观测面，消费 `/admin/state` + `/admin/audit/recent`），
ADR-0017 立了**行动契约**这个协议层产物——它的后果一节里顺带提了 `troubleshoot.html` 一句。
但**没有一条 ADR 说过这个页面是什么**，于是它长成了两副口供：页面自称「排障问答（交互）·
交互调试」，页脚直接打端点名、底部是 debug dump；而 OPS §12 把它当运维面写（"复制出去由
运维自己动手，与本网关无关"）。四个实测事实把这个含糊顶到了台面上：

1. **它只给平台管理员开门**。登录探针打 `/api/v1/admin/state`，而 `/api/v1/admin/**` 在
   Controller 层要求 `role=platform ∧ auth_level>=3`（`AdminController`）⇒ `sre-limited`
   （level 1）**连页面都进不去**——而它正是权限对照里的低密级侧。
2. **三处负状态丢信息**：`meta` 帧没有 `refused` 键（页面那段判拒答的分支是**死代码**，
   拒答渲染成绿色「完成」）；`emitError` 刻意带上了 `refs`/`actions`（注释写明"把它一并吞掉
   等于让客户端在最需要行动清单的时候拿到空手"）而页面只取 `message`；`actions` 为空时整张
   卡片 `display:none`，静默。
3. **面板已经占了"单次请求可见性"的一半**。面板的「请求处理轨迹」按审计行渲染每请求卡片
   （含 `max_level`、`stage_ms` 分段耗时、拒答红框），排障台不能靠"能看到这一次请求"立身。
4. **`/v1` 也带得走契约**。`OpenAiChatSink.done()` 把 `actions` 与 refs 降级渲染成正文
   markdown，所以任何 OpenAI 客户端都能看到命令清单——排障台也不能靠"能看到契约"立身。

决策：**排障台是运维真用面，职责是单次请求的「协议面证据」**。五条：

1. **定位**：同屏呈现 答案 + 结构化行动契约 + 溯源引用 + 运行态元信息。与面板的分工是
   **视角**而非粒度——面板=审计视角（事后、有 `max_level`/`stage_ms`、无 refs/actions），
   排障台=协议视角（实时、有 refs/actions、无 `max_level`/`stage_ms`）。两者互补不重复。
2. **门禁**：任意有效 JWT 可用（放开 platform-only）。
3. **凭据入口**：页面内用户名 + 口令 → `/api/v1/auth/login`。不再要求从终端取 token 粘贴，
   也不再往 localStorage 写 token（只记用户名）。
4. **证据边界**：只消费 SSE 帧，**不读审计**。
5. **状态**：只保留"一次对照对"，**不建历史**。对照模式的定义与判据见 `CONTEXT.md` 权限域。

理由：

① **"运维真用面"与 platform-only 自相矛盾**，且对照模式结构上要求页面能收低密级 token——
不放开，"并排看 L1 与 L3"永远只能靠 CLI（今天正是 `console_client.py --token sre_l1` 在做）。
② **页面内换凭据顺手消解了一个更麻烦的问题**：若维持"粘贴 token"，页面就需要一个探针去确认
token 有效，而候选探针 `/api/v1/copilot/search` 会真的走检索并**落一行审计**（见 `CONTEXT.md`
「审计事件」）；login 本身就是身份确认，这个问题不需要回答。
③ **只吃 SSE 帧**是因为"完整证据"该定义成**客户端可独立验证的那部分**（命令逐字出自哪段原文、
这次走的是哪条路、耗时多少）；密级触达是**服务端权威**、归审计。更要紧的是审计的权限列目前
有一处**已验证的失真**：`IngestionRunner.warmSop` 只按 tenant 分区（`sop:<tenant>:steps`），
`SopFallbackService.lookup(query, service, tenant)` 不收 `authLevel`，兜底还直接
`steps.readAllValues().limit(2)`——于是 tenant-internal 的 level-2 止损段（rb-005 支付网关 /
rb-010 / rb-011 / rb-014）在 L2 直出时对 level-1 主体可达。把一个**已知与权限维度不一致**的
字段摆进"证据面"，比不摆更糟：它给运维一种"系统替我核过了密级"的假安心。
④ **不建历史**沿用仓库已有的同类裁定（OPS §5「Console 档位切换历史面板」）：权威历史是 14 天
滚动的 `logs/audit.jsonl`，浏览器里再造一份必然轮转、无法核查的量具是**选错量具**。
⑤ **`refused` 进 `meta` 帧**而不是客户端按话术前缀识别——不拿话术当协议（PromptAssembler
规则 7、V9 接地判据、逐字导出护栏都在防这件事）；且 `refused` 本来就是 `AnswerPayload` 的
存储合同字段（2026-09-28 为回放路径把它硬编码成 `false` 专门修过一次），它只是没被送上帧。

备选与否决：

| 被否项 | 理由 |
| --- | --- |
| 维持 platform-only，定位成"平台管理员的值班台" | 与"运维真用面"矛盾（低密级侧进不来）；且与面板的门禁完全重合，等于把两个页面绑成同一个受众。 |
| 只贴 JWT（页面不碰口令） | 保住"凭据只在终端换"的既有姿态，但对照模式要两枚 token 就得跑两趟 CLI；且页面仍需一个探针确认 token 有效，而候选探针会污染审计。 |
| 读 `/api/v1/admin/audit/recent` 补 `max_level`/`stage_ms` | 直接违反第 2 条（又变回 platform-only）；作为"可选加成"则让同一页面在不同身份下长得不一样，解释成本高，且把一个已知失真的字段当证据。 |
| 建可翻历史 | 见理由 ④。 |
| 客户端按话术前缀识别拒答 | 在协议之外偷建第二条真相源，话术一改即静默失效——正是本条要修的那类 bug。 |
| 空契约区分"引用里没有"与"被策略判拒" | 后者是全局 Prometheus 计数器（`aiops_guard_action_commands_rejected`），按请求归因要同时扩协议面与指标面；生产就绪"本轮明确不做"清单里已有**不新增 `OpsMetrics` 计数器**的纪律。统一措辞并点明"这是引用集的性质、不是故障"。 |

后果：

- **协议面**：`meta` 帧 6 → 7 键（`+refused`）。它是用户可见状态（用户本来就该知道自己被
  拒答了），不是内部量纲，故与「分段耗时」条"内部耗时不该泄到对外协议面"不冲突。连带
  `acceptance_a3` 的帧形状断言。
- **顺带修的两处纯前端缺陷**（无取舍，不单独立项）：`error` 帧的 `refs`/`actions` 必须渲染
  （后端刻意带上了）；空契约显式说明"本次引用的内容里没有可执行段"。
- **凭据口径扩展**：OPS §1/§9 的"凭据在终端换"扩展为"终端 ∨ 排障台"。三条实现纪律：
  口令只在请求体（`AuthController` 既有口径：绝不入日志/响应）、不落 localStorage / DOM 残留；
  **401 与 429 必须分开显示**（`AuthService` 5 次失败 / 15 分钟锁，两者含义完全不同）。
- **文档连带**：OPS §9 与 §12 的措辞、README 的端点表行、`index.html` 的导航链接文案。
- **已登记待修（本条不修）**：上文理由 ③ 那条 SOP 路径缺 `auth_level` 维度——它是 ADR-0008
  在 L2 静态 SOP 面上的缺口，修法要动 `warmSop` 的分区键与 `lookup` 签名。**在它修掉之前，
  对外不得宣称"静态 SOP 也按密级隔离"。**

**实施后补（2026-10-18 渲染核色，三条都不改上面的决策，只修规格落地时的细节）**：

1. **空契约 Callout 固定 34px 单行**——首版实现是 68px 三行，与"单行紧凑、不挤占正文"的规格
   不符。结论句留在正文，详细解释（"命令住在「排查步骤 > 第N步」编号叶里"）挂 `title`。
2. **差集表的时间行按抖动容差判同**（`nearMs`：绝对 60ms 或相对 20% 以内算一致）。核色实测
   `TTFT 6967ms vs 6964ms` 被高亮成差异行——那 3ms 是模型抖动，高亮它会把本表的核心论据
   （性能两侧一致 ⇒ 分叉发生在引擎层）**说反**。判据：`6967/6964 → same`、`12ms vs 2627ms
   → diff`、`0ms vs 1605ms → diff`。
3. **窄屏 ≤900px 左栏改堆叠**——常驻 300px 左栏照搬到 390px 视口会把报告列压成 90px 宽的
   竖排字（实测 `main` 宽 90px）。媒体查询：左栏转顶栏、对照模式双栏回落单栏、差集表横向滚动。
   桌面形态（300px 常驻左栏）不变——那是这套工作台的人体工学主体。

**核色证据**：1440×900 下跑通 单栏含契约 / 双身份对照 / 拒答闸门 三态 + 390×844 一态，
`console/page errors: none`，正文无裸 `**`，`[参考N]` 悬停 → 来源条 `[N]` 高亮实测命中，
双身份分叉用例两侧 `cache_hit`/档位/快路径/检索耗时全一致。

相关：ADR-0005（账号体系与凭据边界）、ADR-0008（每条共享路径都有权限维度）、ADR-0009（只读可观测
面）、ADR-0017（行动契约，本页渲染的正是它）；操作面见 OPS §9/§12。

**注记（2026-10-19，随 ADR-0021 / 0023 落定）**：上面五条决策**不变**，三处层级与协议面调整：

1. **对照模式降为高级入口**。它从"与单栏并列的模式"降为统一工作台右上角的「高级 · 权限隔离演练」，
   且**预设不再自动切换模式**（实测此前 4 个预设里有 2 个会偷偷把页面切进对照态——那是"夹具感"的
   一半来源）。视觉层级与三层分工见 ADR-0021。
2. **`meta` 帧新增 `gate: none|clarify|refuse`**（与 `refused` 并存，`refused` 保留不删）。本 ADR
   决策⑤把 `refused` 送上帧时，**澄清与拒答在协议面上仍是同一个键**，而 `CONTEXT.md`「回指澄清」
   条明确写着"不是拒答"：模型里有两种状态、协议面只有一种。实测对照（`刚才那个怎么办` →
   `refused=true` / `retrieval_ms=0` / 澄清话术；`今天天气怎么样` → `refused=true` / 2762ms / 拒答
   话术）说明这两条路径的**成因与代价都不同**，压成一个键会让页面只能把它们渲染成同一个徽标。
   不用 `retrieval_ms == 0` 反推：那是拿性能量当状态量，任何一次缓存命中都会让它误判。
3. **拒答时 `done` 帧新增 `near_miss`**：本 ADR 的拒答分支今天 `sink.done(…, List.of(), List.of())`
   ——refs 与 actions 都被丢掉，页面因此拿不到"最接近的候选"。`near_miss` 只带 top-3 候选的
   `service` 与 `error_codes`，不带 chunk_id / 面包屑 / 正文；零召回给空数组。取舍与越权面分析见
   ADR-0023 决策⑤与理由④。

另：本页所在的统一工作台（ADR-0021）里，凭据入口仍按本 ADR 决策②走页内登录，但 token 从"只在内存"
改为存 `sessionStorage`（刷新不掉线、关标签页失效，**不宣称是安全升级**）；页面侧的粘贴 token 入口
退役，`console_token.sh` 保留给脚本与自动化。
