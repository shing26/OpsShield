# 0046. RCA A1：新特征过滤器未通过，OB 的误报不是瞬态尖峰

- 状态：已采纳（2026-11-27，Lead 签收 §5 R1 修订并接受 A1 FAIL；Verifier 复核 HEAD `40db6fc`）
- 日期：2026-11-27
- 契约：`plans/rca-detection-a1-accept.md`（FROZEN）
- 证据：`offline/rca/reports/A1-report.md`

## 背景

v2 冻结算子在 SS dev 有 0.907 覆盖 / 1.3% 误报，在 OB dev 只有 0.480 / 41.3%。
路线 A 的 A1 想在 v2 报警之上加三个判据（C 跨服务一致性、D 持续时间、
P 调用链相关），把两套 dev 同时做到覆盖 ≥80%、误报 ≤5%。

## 决策

**按冻结契约判 A1 FAIL（合规集 0/16），放弃“过滤器”这一族机制。**

## 证据

- SS 最好：0.840 / 误报 0（z0=3.5, k=3, W=60, p=0.6）——过滤几乎免费。
- OB 最好：**0.493 / 误报 16（21.3%）**（z0=3.5, k=4, W=60, p=0.6）。
- 分故障：SS loss −20.0pp、cpu −13.3pp；OB cpu 0.200→0.000、loss −13.3pp。
- 延迟：中位 46s/44s、P90 55s/60.6s，通过。

## 机制结论

1. **过滤器不新增事件，只做重选择**：逐 case 对账（v2 → 过滤，OB）
   `none→det = 0`，覆盖变化来自 FA→后移检出 **+12** 与 检出→miss **−11**，
   净 **+1** 个 case（36→37，0.480→0.493）。要到 0.80 需要净 +24，
   兑换预算根本不够。所以“OB 覆盖 ≥0.80”在这一机制下不可达——
   理由是**没有新增检出**，不是“上限等于基线”（后者是初版报告的错误说法，已更正）。
2. **OB 的注入前报警不是单服务瞬态**：C/D 只拒掉 10–17 个，剩 14–21 个，
   说明它们在时间上持续或跨服务同时出现，与真实故障形态难以区分。
3. **SS 的误报确实是瞬态**：过滤后误报归零，覆盖只掉 6.7pp。
   两套系统的误报成因不同，单一过滤器无法同时适配。

## 否决项

- **放宽 AC-4/AC-5 让 A1 通过**：门槛是预先冻结的；失败原因是机制选错，
  不是门槛太高。
- **继续在 A1 结果上挑窗口/阈值**：看到结果后再改网格即为调参。
- **把 P 升级成门槛**：TT 没有调用图，A2 迁移会直接失效。
- **用 per-system commissioning 绕过跨系统判据**：v3 附录 A 已证失败。

## 后果

- 正面：一次 32 次运行的实验同时否掉了“加过滤器”和“OB 误报是尖峰”两个假设，
  并给出两套系统误报成因不同的证据。
- 负面：检测仍然不可用；路线 A 的 A1 未通过，端到端继续不可用。
- 记录：32 条超 300s 的迟到报警已单列（OB 的 4 个 case），均未计检出；
  dev 每故障样本是 15（3 reps × 5 services），不是 25；P 只用了 callees。
- 后续：下一份契约必须换机制（按指标自适应阈值 / change-point / CUSUM /
  按服务历史分位归一），并且在 dev 上先声明“能否新增检出”，
  不能再把只做减法的过滤器与“覆盖 ≥80%”绑在一起。TT 与 rep 4–5 保持未读。
