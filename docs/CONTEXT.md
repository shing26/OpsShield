# OpsPilot — AIOps 智能排障与契约检索网关

面向微服务与云原生环境的混合检索（Hybrid RAG）与智能故障自查系统：SRE 粘贴报错堆栈或口语化描述，系统经「指纹去重 → 双路召回 → RRF 融合 → 精排裁剪 → LLM 流式生成」输出可溯源的排障步骤。

## Language

### 检索域

**排障请求（Query）**:
一次用户/告警发起的排障输入，可以是口语化描述或错误堆栈。_对外_: 无对外别名。_Avoid_: 问题、提问

**语义块（Chunk）**:
切分产物的原子单位——一个 OpenAPI Endpoint 或一段标题感知的 Markdown 小节，自包含且携带元数据。_对外_: 无对外别名。_Avoid_: 片段、分块、文档

**双路召回（Hybrid Retrieval）**:
ES 倒排（精确符号）与 Qdrant 向量（语义泛化）并行检索后融合的模式。_对外_: 无对外别名。_Avoid_: 混合搜索

**RRF**:
Reciprocal Rank Fusion，倒数排名融合（k=60），将双路排名无量纲合并。_对外_: 无对外别名。_Avoid_: 加权融合

**精排（Rerank）**:
对 RRF Top-20 调用云端 Reranker 二次过滤，裁剪至 Top-3 上下文。_对外_: 无对外别名。_Avoid_: 重排序

**快路径（Fast Path）**:
查询含错误码且 ES keyword 精确命中 Top-1 时跳过 Rerank 的捷径。_对外_: 无对外别名。

**强标识符（Strong Identifier）**:
错误码或全限定名（FQCN）——形状判据非查表判据。词法单一事实源=EsSearchService 的 ERROR_CODE/FQCN 两个形状常量；但两个消费方的**组合判据不同**：快路径只认错误码（+keyword 精确命中 Top-1），FQCN 不参与其判定；防断言语态门认错误码∨FQCN（`hasStrongIdentifier`），query 含强标识符才允许结论式锚定具体事故，否则假设语态作答。_对外_: 无对外别名。_Avoid_: 关键词、特征码（词表会随语料漂移）

**回指澄清（Clarification）**:
识别“依赖上文”的提问（如 `刚才那个怎么办`）并在**检索前**要求补信息的行为——**不是拒答**：拒答是“这次问的东西知识库里没有”，澄清是“这次问的东西不完整”。触发是三重合取——短（≤8 字）∧ 以回指短语开头 ∧ 其后只剩提问尾巴（呢/吧/怎么办…）——另有独立前提：无强标识符（错误码 ∨ FQCN，复用既有单一事实源）；裸的“这/那/它”刻意不在词表内（太常见，误拦会堵住正常提问）。落审计 `mode="clarify"` + `refused=true`，零 LLM、无 refs、不落 `stage_ms`（检索根本没发生）。位置在**缓存之前**（判的是输入形态，与缓存状态无关），仅 L2 期让位给 SOP 直出。**存在的理由**：本系统单轮无会话，把回指句当独立 query 硬检索会命中无关内容并答得自信——对“可信”的伤害大于多问一句。_对外_: 无对外别名。_Avoid_: 追问、多轮（本系统不保留会话，见 ADR-0007/ADR-0013）

**覆盖范围（Coverage）**:
按**调用者身份过滤**后的语料边界声明——覆盖的服务数 / 错误码数 / 语义块数 + 最近重建时间，**提问前可见**（`GET /api/v1/copilot/coverage`），且**从语料现算**、不许手写。存在的理由：知识库覆盖不到的问题上，"答不出来"必须能被读成**边界**而不是**故障**；而清单本身就是越权面——给外部租户列出内部租户的服务名，等于把语料边界泄出去。_对外_: 无对外别名。_Avoid_: 知识库清单（易读成静态文档）、支持列表

### 风暴防线域

**指纹（Fingerprint）**:
`SHA256(service + "|" + env + "|" + normalized_error_msg)` **取摘要前 128 位**（32 位十六进制）——归一化剥离时间戳/数字/ID 后的错误签名。分隔符与长度都写明，是因为指纹同时是 L1 缓存键的组分、SSE meta 的回传值、以及反馈端点归档"问题"的键：只写 `SHA256(...)` 会让人以为是 64 位（2026-09-27 实测对照时确实这样误解过一次）。截断到 128 位的碰撞界约 2^64，对告警去重足够。**注**：该截断在仓内**只有实现、没有决策记录**（无 ADR/注释，见台账 2026-09-27 节）。**2026-10-17 拆分**：本式只对**未带 `alertId` 的请求**成立（查询指纹）；带 `alertId` 时走**告警身份**（见下条）——外部规则模板会把 `$value` 渲染进注解，文本归一化护不住（台账 2026-10-17 §3.1）。_对外_: 去重键。_Avoid_: 签名、哈希键

**告警身份（Alert Identity）**:
`SHA256("alert-id|" + alertId)` **取摘要前 128 位**（32 位十六进制），**不透明**、不做文本归一化。`alertId` 由 `alert_bridge.py` 从 `alertname/job/error_code/status` 四元组定长派生（`firing` 与 `resolved` 是两个身份），**与 message 文本无关**——规则模板里的 `$value` 数值抖动因此不再改变身份。服务端不解析其含义，只当缓存/收敛键。字段缺省（人工提问、既有自举告警源不传）时回退查询指纹，行为逐字不变。告警身份同时进 L1 键、SingleFlight 组键、SSE `meta`、审计列与反馈归档键。**边界（如实登记）**：这是**约定隔离，不是密码学隔离**——`service/env` 是自由文本，理论上仍可构造出撞车的输入；真正的权限隔离是与本指纹同列的 `tenant×authLevel`。_对外_: 无对外别名。_Avoid_: 会话 id（本系统单轮，见 ADR-0007/ADR-0013）

**事故（Incident）**:
一次由**上游定义**、可在审计面整段读出的故障单元。本系统里它恒等于 Alertmanager 一个告警分组的**一次生命周期**（同 `group_by`、同起点）——"哪几条告警属于同一次事故"的判定权归上游，本系统不重新发明（同一立场见谱系表 ②「异常判定权恒归上游」）。一次事故含 N 条告警，N 条**各自仍有独立的排障回答**：**关联，不是归并**（不把 N 条压成一条 query，也不把 N 个答案并成一个）。_对外_: 无对外别名。_Avoid_: 调用链（那是某一调用方自己的一段连续调用，是另一个东西）、告警分组（那是 Alertmanager 的外部概念，本词指这次事故本身）

**告警分组身份（Alert Group Identity）**:
上面那次事故的**不透明关联键**：`am-` + `SHA256(groupKey + "|" + 组内最早 startsAt)` 取摘要前 128 位（32 位十六进制）。拼 `startsAt` 的原因：`groupKey` 是**路由桶 id 而非事故 id**——它不含时间维，同一条规则下周再 fire 会落回同一个桶。它随 `X-Trace-Id` 请求头发给网关、落在审计行 `trace_id` 列，因此"一次事故里的 N 条告警"可用 `grep '"trace_id":"am-…"'` 整段取出。**只做关联，不进任何键**（与告警身份的分工：那条回答"这一条告警是什么"，进 L1 缓存与单飞组键；这条回答"这几条告警属于哪一次事故"，不改检索、不改缓存）。_对外_: 无对外别名。_Avoid_: 事故 id（中文侧统一用"告警分组身份"）、trace_id（那是传输层的列名，不是这个概念的命名）

**投递策略（Delivery Policy）**:
Bridge 或 Producer 为一次告警投递选择的来源规则，规定哪些发送前闸门按什么顺序适用、配额取自实时读取还是周期快照，以及是否启用来源冷却。_对外_: 无对外别名。_Avoid_: 告警规则（它产生候选，不决定投递）、重试策略（系统没有自动重试）

**投递尝试（Alert Delivery Attempt）**:
一份已翻译、可发送的告警请求连同来源上下文进入共用投递 seam 的单位；一次尝试至多发出一次 HTTP 请求，并以一个投递结果结束。Alertmanager 翻译与 Producer 异常判定发生在尝试之前。_对外_: 无对外别名。_Avoid_: 告警请求（易与 ChatRequest 混淆）、webhook（只是 Bridge 的输入形态）

**投递结果（Alert Delivery Outcome）**:
一次投递尝试的封闭结局：跳过（Skipped）、送达（Delivered）、被拒（Rejected）、传输失败（TransportFailed）。Skipped 表示请求未发出；Delivered / Rejected 表示已收到 HTTP 响应；TransportFailed 表示没有拿到响应，401 的自愈动作不改变其 Rejected 分类。_对外_: 无对外别名。_Avoid_: 发送成功 / 失败（会把"是否发出"与"服务端是否接受"压成一件事）、emit / sent_ok（它们是台账字段，不是领域结局）

**告警台账（Alert Ledger）**:
Bridge 与 Producer 追加写出的 JSONL 证据流，记录闸门判定、登录失败、投递结果与来源特有上下文；它不是应用日志，也不以成功发送为前提。_对外_: 无对外别名。_Avoid_: 审计日志（那是 Chat 请求的权限留痕，不是告警来源的处置证据）、事件日志（过泛）

**滑动窗口（Sliding Window）**:
按 `来源×指纹` 维护的 Redis ZSET 聚合计数窗口（manual 30s / alert 60s），仅服务 dedup 计数与"风暴收敛"叙事；穿透闸门的唯一归属是单飞，窗口不做排除。_对外_: 无对外别名。_Avoid_: 防抖（口语可用，代码中统一 Sliding Window）、"窗口内仅首条穿透"（旧口径与实现不符，2026-09-13 grill 裁定废止）

**单飞（Single-Flight）**:
同指纹并发请求挂起等待首条结果并复用的进程内合并机制，key 掺 authLevel 防跨权限复用。_对外_: 并发合并。_Avoid_: 请求合并

**来源（Source）**:
排障请求的发起方标记：`alert`（告警系统转发）或 `manual`（SRE 手动粘贴），影响去重窗口配置。_对外_: 无对外别名。

### 缓存域

**L1 精确缓存**:
`tenant + authLevel + 指纹` 为 Key 的 Redis 哈希缓存（指纹 = 告警身份或查询指纹，见风暴防线域），TTL 2h。**2026-10-17 起不再自己哈希 query 文本**：原式 `SHA-256(normalize(query))` 会让同一告警每次重发都成新键（台账 2026-10-17 §3.1）；身份归一化的职责收在 `FingerprintService` 一处。**随之取消旧键的 `toLowerCase` 折叠**——大小写不同即不同问题：原 L1 与 SingleFlight 用着两套归一化口径，现在统一到指纹一处。**已知边界（2026-10-03 登记，live QA F-4）**：门控拒答**也写 L1**（同键重发直接回放拒答，省一次检索）——代价是语料重灌补上新内容后，同键最长 2h 内仍回放旧拒答；运维 SOP：reingest 后用**改变措辞**的 query（不同指纹）验证新语料，别复用旧原句。触发线：若该 2h 窗口内发生"补了内容仍漏检"的漏检事故 → 缩短拒答类条目的 TTL。_对外_: 无对外别名。_Avoid_: 热缓存

**L2 语义缓存**:
Qdrant 专属 Collection，**仍按 query 文本语义**召回（余弦相似度 > 0.95 判定命中），跳过检索与 LLM 直接回放答案；payload 携带 `max_auth_level` 防权限泄漏。**2026-10-17 口径**：拆身份只作用于 L1 与 SingleFlight 的**精确键**，L2 不动——它的职责是"换了措辞的同一个问题"也能命中，改成身份反而丢掉这个能力。_对外_: 无对外别名。_Avoid_: 向量缓存

**回放（Replay）**:
等待者/缓存命中者收到完整答案一次性写入自身 SSE 流的行为，区别于实时流式。_对外_: 无对外别名。

### 降级域

**Level 0（正常）**: ES+Qdrant 双路 + Rerank + LLM 全链路；相关性门控生效。_对外_: 无对外别名。
**Level 1（高负载）**: 摘除向量路与 Rerank，纯 ES 关键词召回（检索侧等同 `es_only` 模式）。**代价有两项**：检索质量下降（语义 Hit@1 88.2%→70.6%），且**门控降级**——摘除 Rerank 后无相关性分数可依，门控从「相关性级」退为「零召回级」，即"不知道就不答"在降级期被弱化。取舍与重开触发线见 [ADR-0012](adr/0012-degradation-cost-semantics.md)。_对外_: 无对外别名。
**Level 2（熔断）**: 切断 LLM，直出 Redis 预热的静态 SOP 止损清单。
_对外_: 无对外别名。_Avoid_: 熔断级别、降级档位（统一 Level 0/1/2）

**静态 SOP**:
入库时按 `error_code/service` 预热进 Redis 的止损步骤清单，Level 2 兜底数据源。_对外_: 无对外别名。

**档位转移（Degrade Transition）**:
档位发生变化这一**事件**本身，落审计 `ev="degrade_transition"`，带 `from`/`to`/`cause`。为什么不能只靠审计行的 `degrade_level` 字段反推：字段答的是"**这次请求时**是几档"，切换时刻要靠请求密度间接推断，无请求的区间里切换会被整段漏掉。`cause` 是**有限词表**：`inflight`（在途超阈→L1）/ `llm_failure`（连续失败达阈→L2）/ `load_subsided`（负载回落→L0）/ `cooldown_expired`（冷却到期半开→L0）/ `manual` / `manual_clear`。**量具边界**：状态机是**拉模型**（无独立定时器），转移在计数器变化处（enter/exit/llmFailure/llmSuccess/manual*）与 `current()` 被调用时被观察到——负载回落因此不依赖后续请求即可落痕，但"既无请求又无人看 `/state`"的静默期内的切换会与下一次观察合并。_对外_: 无对外别名。_Avoid_: 降级日志（日志是过程，这是可复核的事件序列）

### 权限域

**auth_level**:
数据密级与用户凭证等级，整数 1/2/3（1=公开 SOP，2=内部复盘，3=含生产配置）。硬过滤规则：`chunk.auth_level <= user.auth_level`，在 ES 与 Qdrant 引擎层强制注入。_对外_: 无对外别名。_Avoid_: 角色（role 是另一维度，见下）

**role**:
用户职能（sre/dev/manager），仅用于审计与 Prompt 个性化，不参与数据过滤。_对外_: 无对外别名。

**租户（Tenant）**:
数据归属与隔离的第一维度，与 auth_level 同级在 ES/Qdrant/L2/SOP 四面引擎硬过滤（`metadata.tenant` term 等值 + range lte 双 must）。内部工具形态恒 `tenant-internal`；tenant claim 缺失/空白/超 64 在入口 401。_对外_: 无对外别名。_Avoid_: 工作区、命名空间（缓存前缀是另一回事）

**对照模式（Contrast Mode）**:
排障台里"同一个 query 用两个身份各问一次、两份结果并排钉住"的模式，用来肉眼核权限维度（tenant × auth_level）是否真的在引擎层生效。判据是**低密级侧的引用集里不出现高密级 chunk**——不是"两个答案措辞不同"：措辞随模型浮动，引用集才是权限维度的直接证据。**2026-10-19**：视觉层级从"与单栏并列的模式"降为统一工作台右上角的**高级入口**（ADR-0021），预设不再自动切换模式。_对外_: 权限隔离演练（不叫"沙箱"——它不是隔离环境，是同一页面的对照视图）。_Avoid_: 对比模式、权限对比（都易读成"比大小"，本词比的是同一问题的两种可见性）

**账号（Account）**:
H2 主库中的一行用户记录（sub + bcrypt 口令 + tenant + auth_level + disabled + token_ver），权限维度的唯一真相源；JWT 只是账号身份的短时载体（24h）。_对外_: 无对外别名。_Avoid_: 用户（user 指运行时 UserContext）

**吊销版本（token_ver / tver）**:
账号行上的整数游标，签进 JWT 的 `tver` claim；`JwtAuthFilter` 每请求比对 DB 值，不等即 401。disable/passwd/rotate 均 bump——改一行即全局失效该用户所有存量 token，无需黑名单。_对外_: 无对外别名。_Avoid_: JWT 黑名单（明确否决的方案）

**审计事件（Audit Event）**:
每 chat/search 请求落一行 JSON 到 `logs/audit.jsonl`（sub/tenant/level/query 截断/fp/cache_hit/mode/**degrade_level**/refused/max_level/took_ms + 请求关联键），回答"谁查过什么、答案触到哪个密级、**这次请求处在哪一档降级**"，是权限引擎层的可核查闭环。**`degrade_level` 是必需列而非冗余**：`mode` 有两个来源（L1 降级按档位传 `es_only` / 检索腿超时后 `effectiveMode` 也是 `es_only`），单看 `mode` 无法判定"这次是不是负载触发的降级"。_对外_: 无对外别名。_Avoid_: 应用日志（业务日志非合规留痕）

**请求关联键（request_id / trace_id）**:
审计行上的两个身份键，**并存且互不覆盖**。`request_id` = 服务端为每次 HTTP 请求自生的 8 位短 id（`RequestIdFilter` 注入 MDC，同时进 app.log 与审计行），语义是"这一行是哪个请求产生的"，**服务端权威**、调用方输入顶不掉。`trace_id` = **调用方提供**的关联键（请求头 `X-Trace-Id`，8–64 位 `[A-Za-z0-9_-]`，空白按未提供，非法即 400 + 留痕），语义是"这条调用链分几步问过、都问了什么"——凑不上它时，被测 agent 的多步调用在审计里串不成一条**调用链**（既有 `fingerprint` 是**内容派生**的"问题身份"，三步问不同错误码即散成三个，担不起调用链身份）。**该列有两个生产者**（2026-10-17 起）：agent 自述的调用链 id，以及告警桥派生的**告警分组身份**（`am-…`，即一次事故，见风暴防线域）——列语义是"调用方给的关联键"，故两者共用一列而非各开一列。排障时按问题选：查单次请求用 `request_id`，查跨步链路用 `trace_id`（调用链），查一次事故里的多条告警用同一个 `trace_id`（`am-…`）。_对外_: 无对外别名。_Avoid_: 会话 id（无状态单轮，见 ADR-0007/ADR-0013）、traceId 大小写混写（落盘统一 `trace_id`）

### 重建域

**blue/green 重建（Staging Reingest）**:
知识库更新的安全流程：写时间戳物理库 `<base>-<ts>` → 计数硬验收 → 单请求原子换 ES/Qdrant 别名 → 删旧库；任何失败保留旧别名指向。查询侧永远只认别名（`opspilot-chunks-read` / `opspilot-vectors-live`），零空窗。_Avoid_: 热更新、滚动重建（旧"先删后建"是被否决的反模式）

**回滚（Alias Rollback）**:
改别名指回上一版物理库（若未清理）即秒级回退，重建失败无需恢复数据。_对外_: 无对外别名。

### 评测域

**Golden Dataset**:
68 组标注样本（34 精确错误码 + 34 口语化语义），与合成语料同源，ground truth 为期望 chunk_id 集合。2026-10-03 扩样：纳入两条被置信度门控误拒的口语极值（见 live QA F-3），盯住“能答的别拒”。2026-10-07 扩样：本机辖区真实事故系列 rb-101~105 的口语化覆盖 + 旧系列（重编号 rb-111~115）两篇。_对外_: 无对外别名。

**越狱用例（Jailbreak Case）**:
诱导模型输出越权内容的对抗 Prompt，验收标准是引擎层过滤使其召回为空，而非模型自觉。_对外_: 无对外别名。

**TTFT**:
双口径——`connect`（SSE 连接建立）与 `first_token`（首个内容 token），报告分别记录。_对外_: 无对外别名。

**答案接地（Grounding）**:
"答案里出现的东西是否都有据"的判据——补防幻觉链路的**事后**环。在线既有闸门全在事前（置信度门控拒答）或通用文本层（逐字导出护栏），故系统能保证"没证据就不答"，却不能保证"答了的内容都有证据"。当前判据只覆盖**错误码**这一种精确符号：答案中出现的错误码必须落在本轮 refs 的 `metadata.error_codes` 并集内，**幻觉率 = 未命中比例**（实现 `offline/grounding.py`，live 断言 V9）。已知边界：runbook 步骤编号（pm-*/rb-*）不在管辖内（那类归 V4 语态锁与人工评审）；query 自身含语料外错误码时，模型复述会被计为无据（方向保守）。_对外_: 无对外别名。_Avoid_: 引用正确率（那是"标号是否支撑该句"，需 LLM-as-Judge，本判据不做）、幻觉率（不加限定语时易被误读为覆盖全部幻觉形态）

**同代门闩（Same-Generation Gate）**:
"文档里的数字必须等于随附产物算出来的数字"这一约束的机器判据，分两个面：**面一**「报告↔语料」——对语料字节集、切分产物、评测集取内容摘要，与登记比对（判据是**内容**不是 mtime：CI 的 `git checkout` 会把所有 mtime 刷成检出时刻，时间戳判据在那里恒真、等于空转）；**面二**「文档数字↔产物」——按登记表**每次现算**产物真值，与文档里的字面量比对，不存数值快照。面一同代**不等于**面二同代：报告是对的，人把它抄进 README 时抄错或改了产物忘了改文档，面一完全看不见。_对外_: 无对外别名。_Avoid_: 数字校验、metrics 校验（门闩只对登记过的数字负责，不做全文扫描）

**变异验证**:
关键判据的验收方法：把被测面**改坏**必须变红、**复原**必须变绿——红不了说明这道闸是空的。它是**方法**，不是某一组用例（命令安全那组只是它的一个应用）。_对外_: 安全回归测试（改坏必红、复原必绿）。_Avoid_: 变异测试（那是通用的测试技术名，本词指本仓对关键判据的验收纪律）、防空跑

**触发线（Trigger Line）**:
债务的到期日——一个**可判读**的条件句（到点必须做，未触发不做）。不可判读的触发线等于没有触发线，因为没有任何时刻会让它到期。_Avoid_: TODO、待优化、以后再说

**误拒 / 漏拒（False Refusal / Missed Refusal）**:
门控的两类错误，方向相反且都伤系统：**误拒** = 本可作答却拒答（伤可用性——用户问了知识库里有的东西，却被告知"无相关参考"）；**漏拒** = 本无据却作答（伤可信度——正是"不知道就不答"要挡的那类）。两者必须**一起看**：单看任一个都能被一个极端阈值刷到很好看（全拒 → 漏拒 0；全答 → 误拒 0）。度量产物 `offline/eval/reports/gate_matrix.md`。_对外_: 无对外别名。_Avoid_: 拒答率（那只是次数，不含正确性）

**分段耗时（Stage Timings）**:
一条请求的时间去哪儿了——检索分腿（`es`/`vector`/`rrf`/`rerank`）+ `retrieval` + `llm_ttft` + `llm` + `l2_store`，随 chat 审计行落 `stage_ms` 嵌套对象（**不落 SSE 帧**：那是对外协议面，内部耗时不该泄到那里）。口径两条易误读：`vector` 段**含该腿内的 embedding 调用**；`rerank = 0` 表示**未调用**（快路径/es_only/降级）而非"很快"——**但 sub-ms 段例外**：`rrf` 是纯计算（恒 <1ms），mock 后端下的 `rerank` 亦如此（实测：`/search` 返回非零 `rerank_score` 证明已应用，审计行却是 0），故"是否调用"请以 `mode`/`fast_path` 为准，`0` 只是"没测出耗时"。非 chat 路径传 `null` → 不落字段（"没测"），与"测得为 0"是两回事。_对外_: 无对外别名。_Avoid_: 耗时（不指明分段时无法回答"时间花在哪"）

**答案反馈（Feedback）**:
人把"这个答案不对"告诉系统的入口（`POST /api/v1/copilot/feedback`），落审计 `ev="feedback"`。**按 fingerprint 归档**而非 request_id——fingerprint 标识的是**问题**不是某次生成，而"复盘→知识回灌"要沉淀的正是知识（问题）。不占配额：反馈是治理信号不是成本，若占配额，用户会在配额耗尽时放弃上报坏答案。它是"复盘→知识回灌"（OPS §5.1 在案债务）的前置入口。_对外_: 无对外别名。_Avoid_: 点赞、评分（都易被读成产品功能，而它是治理信号）

### 输出域

**行动契约（Action Contract）**:
答案下方"下一步该跑什么"的可复制命令清单，**命令不是模型生成的**——从本次引用的 chunk 原文逐字抽出，经四层只读策略（工具白名单 / 子动词闭集 / 外壳负载递归 / 旗标与重定向）核准，认不出的形态判拒并计数。**契约 ⊆ 引用是构造保证**：只从本轮 refs 的 chunk 里抽，因此租户与密级闸不在此重设。网关自身零写操作、无执行回路，复制出去由运维自己动手。两个协议面各有其形：SSE 面走 `done` 帧的结构化 `actions`（恒给键，空给 `[]`），OpenAI 面因无结构化帧位而降级渲染成正文 markdown。_对外_: 只读命令清单。_Avoid_: 建议命令、推荐操作（都会读成模型生成的）；runbook（那是语料里的文档形态，这是运行时产物）

**闸门（Gate）**:
这一次请求被**哪道闸**拦下的协议面标记：`none`（正常作答）/ `clarify`（回指澄清，零检索零 LLM）/ `refuse`（知识库无据，检索跑完但低于阈值）。进 SSE `meta` 帧（`gate`），与 `refused` 并存。**必须与"拒答"分开命名**：`CONTEXT.md`「回指澄清」条明确写着"澄清不是拒答"——把两者压成一个 `refused=true` 会让页面只能把它们渲染成同一个徽标，而它们的成因与代价都不同（零检索 vs 跑完检索）。**不得用 `retrieval_ms == 0` 反推澄清**：那是拿性能量当状态量，任何一次缓存命中都会让它误判。_对外_: 无对外别名。_Avoid_: 拒答（作为统称——它会吞掉澄清）、闸门类型（口语可用，字段名统一 `gate`）

### 部署域

**存储模式（Storage Mode）**:
`opspilot.storage.mode = live|memory` 的**配置期**开关：`live` = 真中间件（ES + Qdrant + Redis，缺则启动失败，与历史行为一致）；`memory` = 三者**全部**由进程内实现承接（语料从 `offline/corpus/chunks.jsonl` 读进内存），零外部依赖。**默认 `live`、不自动回退**——中间件可达性是**运行期事实**、会抖，把配置期开关套到它上面会产出"同一份代码两次启动跑在不同后端、页面数字却长得一模一样"的假绿实例（[ADR-0022](adr/0022-standalone-storage-mode.md)）。内存实现**复用同一份** `tenant × auth_level` 过滤判据（`IdentityFilter`）与只读策略，**不另写一套**——否则它就成了绕开权限引擎的旁路，而权限隔离正是这个系统最贵的能力。启动摘要与 `/api/v1/admin/health` 自报 `storage=memory` / `backend=in-memory`，让"我这次跑的是哪条链路"成为一条可 grep 的事实。**不承诺任何检索质量数字**：向量是词法哈希、精排是词面覆盖度，拒答门控的行为会随**模型轴**（`dashscope.mode`）变（见 ADR-0022 注记）。_对外_: 零依赖试跑。_Avoid_: 降级档 Level 3（内存实现是**换了一条链路**，不是同链路在压力下的取舍）、离线模式（`memory` 不承诺离线——`DASHSCOPE_MODE=live` 下仍要联网）
